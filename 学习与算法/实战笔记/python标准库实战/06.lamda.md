# Python lambda：一行现造一个匿名函数，当值来传

lambda 解决的问题是：**需要一个小函数递给别的函数用，但专门 def 一个名字太重**。算法题里最常出现在 `sorted` / `max` / `min` / `heapq` 的 `key=`，以及"目标函数参数比调用方将来会给的多，需要提前捆一个进去"（闭包工厂）的场景。

---

## 思路

Python 里函数是普通的值：可以赋给变量、当参数传、当返回值递出去。但用 `def` 造函数必须起名字、占好几行、写在别的地方——当你只要一个"用完即弃的小函数"时太笨重。

lambda 是**函数的字面量**。就像 `3` 是 int 的字面量、`[1, 2]` 是 list 的字面量，`lambda x: x + 1` 是**函数**的字面量：写在哪一行，哪一行就当场出现一个函数值。

> [!tip]- 核心思路
> **`lambda 参数: 表达式` = 现场造一个匿名函数，冒号后面的表达式自动 return。**
>
> ```python
> f = lambda x: x + 1     # 与下面的 def 完全等价
>
> def g(x):
>     return x + 1
>
> f(10)                   # 11
> type(f) is type(g)      # True —— 造出来的是同一种东西
> ```
>
> 判断依据：把 `lambda` 换成 `def`、给冒号后面套上 `return`，读得通就理解对了。

---

## 1. 导入与创建

不需要任何导入，`lambda` 是语言关键字。

> [!success]- 基础语法
> ```python
> add     = lambda a, b: a + b     # 两个参数
> square  = lambda x: x * x        # 一个参数
> get_ten = lambda: 10             # 零个参数
> pick2nd = lambda pair: pair[1]   # 参数可以是任何对象
>
> add(2, 3)     # 5
> get_ten()     # 10
> ```

---

## 2. 核心操作

| 操作 | 作用 | 时间复杂度或注意事项 |
| --- | --- | --- |
| `lambda x: expr` | 造一个匿名函数（一个值） | $O(1)$，只造不执行 |
| `f = lambda x: expr` | 起名保存 | 能这么写就该改用 `def`（PEP 8） |
| `sorted(xs, key=lambda x: x[1])` | 当参数递给高阶函数 | **最主要的用途** |
| `return lambda x: expr` | 当返回值交出去 | expr 引用外层变量 → 闭包 |
| `(lambda x: expr)(v)` | 造完立刻调用 | 少见；多半直接写表达式更清楚 |

> [!example]- 最小示例
> ```python
> pairs = [("b", 3), ("a", 1), ("c", 2)]
> print(sorted(pairs, key=lambda p: p[1]))
> # [('a', 1), ('c', 2), ('b', 3)]
> ```

---

## 3. 关键行为与边界

lambda 和 def 造出来的函数**是同一种东西**（`type` 相同），唯一区别：lambda 没名字、身体只能是**一个表达式**。

> [!tip]- 为什么这样做
> `key=lambda p: p[1]` 里，`sorted` 拿到的是**函数本身**，它内部对每个元素各调用一次来取排序键。你递进去的是"怎么取键"这个**方法**，不是键的值。这就是 lambda 存在的意义：**把「怎么做」包成一个值传来传去**。

> [!warning]- 边界条件
> - 身体只能是**一个表达式**：不能写 `=` 赋值、不能写 `for`/`while`/`if` 语句（三元表达式 `a if c else b` 可以）、不写 `return`（自动返回表达式的值）。
> - 逻辑超过一行 → 老老实实用 `def`，lambda 塞不下。
> - lambda 引用外层变量时，存的是**变量本身，不是定义那一刻的值**（晚绑定，见易错点三）。

## 4. 实例一：sorted / max 的自定义键（最常见）

输入是复合结构（元组、字典），要按其中**某一部分**排序或取最值；默认比较规则不满足，所以递一个"取键函数"进去。

> [!success]- 完整实现
> ```python
> students = [
>     {"name": "张三", "score": 88},
>     {"name": "李四", "score": 95},
>     {"name": "王五", "score": 71},
> ]
>
> # 按分数从高到低排
> by_score = sorted(students, key=lambda s: s["score"], reverse=True)
> print([s["name"] for s in by_score])   # ['李四', '张三', '王五']
>
> # 分数最高的那个人
> top = max(students, key=lambda s: s["score"])
> print(top["name"])                     # 李四
> ```

主流程：`sorted` 对每个元素 `s` 调一次 `lambda s: s["score"]`，拿返回值排序。最容易写错的位置：写成 `key=s["score"]`（`s` 根本不存在）或 `key=lambda s: s["score"]()`（分数是 int，不能调用——多按了执行按钮）。

## 5. 实例二：闭包工厂——把参数提前捆进函数再交出去

场景：目标函数要**两个**参数，但未来的调用方（回调、dispatch、`key=` 槽位）只会喂**一个**。解法：外层函数先收下多出来的那个参数，返回一个 lambda 把它**焊**在身上。

> [!success]- 完整实现
> ```python
> def make_multiplier(factor):
>     return lambda x: x * factor    # factor 被焊进新函数
>
> double = make_multiplier(2)
> triple = make_multiplier(3)
>
> print(double(10))          # 20
> print(triple(10))          # 30
> print(double is triple)    # False —— 两个独立函数，各揣各的 factor
> ```

关键在时间线：`make_multiplier(2)` **早就返回退场了**，但 `double` 仍然记得 `factor=2`——内层函数把外层变量"抱走"活了下来，这就叫**闭包（closure）**。

> [!summary]- 当前实例复杂度
> - 时间复杂度：造一个闭包 $O(1)$；每次调用 $O(1)$（一次乘法加普通函数调用开销）。
> - 空间复杂度：每个闭包额外 $O(1)$（存一个对 factor 的引用），返回结果不占额外空间。

**本项目落点**：`hpc_agent/router.py` 的 `select_router` llm 分支——

```python
return lambda question: llm_route(question, client=client)
```

`client` 就是这里的 `factor`，`question` 就是 `x`：`llm_route` 要两个东西，调用方以后只给 `question`，所以出厂前把 `client` 焊进去。

## 6. 与相近写法怎么选

| 需求 | 推荐写法 | 原因 |
| --- | --- | --- |
| 一次性小函数递给 `key=` | `lambda` | 就地写、不用起名 |
| 逻辑超过一个表达式 | `def` | lambda 塞不下语句 |
| 只是取下标/取属性 | `operator.itemgetter(1)` / `attrgetter("x")` | 意图更明确，还更快 |
| 固定已有函数的部分参数 | `functools.partial(f, b=2)` | 标准库替你写包装 |
| 要复用、要测试、要写文档 | `def` | 有名字、有 docstring、可单测 |

## 7. 常见易错点

> [!warning]- 易错点
> - **多按 / 漏按"执行按钮"**：`key=len()` 当场执行、报 TypeError；`return llm_route` 裸交出去、参数没捆上。规则：**递工具不带括号，执行才带括号**。
> - **往 lambda 里塞语句**：`lambda x: y = x + 1` 是语法错误。身体只能是一个表达式，要多行就换 `def`。
> - **循环里的晚绑定**：
>   ```python
>   fs = [lambda: i for i in range(3)]
>   print([f() for f in fs])        # [2, 2, 2]，不是 [0, 1, 2]！
>   ```
>   lambda 捕获的是变量 `i` 本身；循环结束时 `i = 2`，三个函数看到的是同一个 `i`。修法——用默认参数当场"拍照"：
>   ```python
>   fs = [lambda i=i: i for i in range(3)]
>   print([f() for f in fs])        # [0, 1, 2]
>   ```

---

## 复杂度

> [!summary]- 复杂度
> - 造 lambda：$O(1)$——只创建函数对象，不执行身体。
> - 调用：与同逻辑的 `def` 完全相同，就是普通函数调用。
> - 闭包额外空间：$O(k)$，$k$ 为捕获的外层变量个数（存的是引用）。

## 一句话总结

lambda 是**函数的字面量**——`lambda 参数: 表达式` 当场造一个自动 return 的匿名函数当**值**用；看到"要把小函数递给别人"或"参数比调用方会给的多、要提前捆"，就是它的触发信号。

## 模板归纳

看到以下信号时，优先想到 lambda：

- `sorted` / `max` / `min` / `heapq` 要按复合结构的某一部分比较 → `key=lambda ...`
- 目标函数的参数比调用方将来会给的多 → 闭包工厂捆绑
- dispatch 表 / 回调槽位需要"挑一个函数稍后执行"

```python
# 排序键
sorted(items, key=lambda x: x[1])

# 闭包捆绑：f 需要 (a, extra)，但调用方只会给 a
def bind(extra):
    return lambda a: f(a, extra)
```
