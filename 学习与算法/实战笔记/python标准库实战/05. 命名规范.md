
# Python 符号与命名规范：`*` / `**` / 下划线家族

`*`、`**`、下划线（`_` / `__x` / `__x__`）在 Python 里**同一个符号在不同位置意思完全不同**：`*` 在函数定义处是"收集"、在调用处是"展开"；下划线有的是**你给读者的约定信号**（无语言魔法），有的是**Python 定义的特殊名**（有魔法）。分不清就会看不懂别人代码、或误用私有 API。

来源：task_010/011 里真实出现的 `def _create(self, **kwargs)`、`_parse_response`、`TOOL_SCHEMAS`、`__file__`（2026-07-21）。

---

## 思路

这些符号没有"一个含义"，只有"在某个位置的含义"。判断顺序永远是**先看它在哪**（函数定义 / 调用 / 赋值 / 名字开头结尾），再定意思。命名下划线更要分清两问：**这是我起的名（约定），还是 Python 起的名（内建）？**

> [!tip]- 核心速查
> ```python
> def f(*args, **kwargs): ...   # 定义处：收集位置参数/关键字参数
> f(*mylist, **mydict)          # 调用处：把 list/dict 展开成实参
> a, *rest = [1, 2, 3]          # 赋值处：* 吞掉剩余 -> rest=[2,3]
>
> _internal  = 1                # 单前缀：约定"内部用"，无魔法
> class_     = 1                # 单后缀：避开关键字 class，无魔法
> __mangled  = 1               # 双前缀(类内)：名字改写，防子类覆盖
> __file__                     # 双前后缀(dunder)：Python 定义的特殊名
> ```
> 不变量：`*/**` 看**位置**定义/展开；下划线看**是不是 dunder** 定"约定 vs 内建"。

## 2. `*` 与 `**` 的四种位置

| 位置 | 写法 | 作用 |
| --- | --- | --- |
| 函数定义·收集 | `def f(*args, **kwargs)` | 多余位置参数进 `args`(tuple)，多余关键字进 `kwargs`(dict) |
| 函数调用·展开 | `f(*seq, **mapping)` | 把 `seq` 拆成位置实参、`mapping` 拆成关键字实参 |
| 赋值·剩余 | `a, *rest = [1,2,3]` | `*rest` 吞掉剩下的元素 → `[2,3]` |
| 定义·强制关键字 | `def f(a, *, b)` | 光杆 `*` 后面的参数**只能按名字传** |

> [!example]- 最小示例（全来自你见过的形状）
> ```python
> # 收集：FakeLLM._create 就是这么接住你所有参数的
> def create(**kwargs):
>     return kwargs
> create(model="m", temperature=0)     # {'model': 'm', 'temperature': 0}
>
> # 展开：把一个 dict 摊成关键字实参
> cfg = {"model": "m", "temperature": 0}
> create(**cfg)                        # 等价 create(model="m", temperature=0)
>
> # 强制关键字：webhook demo 里 def send(*, to, body) 就靠这个
> def send(*, to):                     # 必须 send(to=...)，不能 send("x")
>     return to
> ```

## 3. 下划线家族（最容易混）

| 写法 | 名字 | 谁起的 | 含义 |
| --- | --- | --- | --- |
| `_name` | 单前缀 | **你** | 约定"内部/私有，别从外面 import"，语言不拦你 |
| `name_` | 单后缀 | 你 | 避开关键字/内建名冲突：`class_`、`type_`、`id_` |
| `__name` | 双前缀（类内） | 你 | **name mangling**：类里 `self.__x` 被改写成 `_类名__x`，防子类误覆盖 |
| `__name__` | 双前后缀 dunder | **Python** | 语言定义的特殊名（`__init__`/`__file__`/`__name__`…），别自造新的 |
| `_` | 单独一个 | 你 | 一次性丢弃变量：`for _ in range(3)`；REPL 里是上个结果 |

> [!tip]- 你问的 `_file` vs `__file__`——本质区别
> - **`_file`**：只是一个**普通变量名**，前面加一根下划线纯粹是给人看的"这是内部用"信号。Python **没有**任何针对它的特殊行为，你不写它它就不存在。
> - **`__file__`**：是 **dunder（double underscore）**，Python **自动**在每个模块里设好的特殊属性，值是"当前这个 .py 文件的路径"。你没定义它，导入模块时解释器就填好了。sys.path 那篇笔记里 `Path(__file__).resolve().parent` 就是靠它拿到"本文件在哪"。
> 一句话：**`_file` 是你起的名（约定，无魔法）；`__file__` 是 Python 起的名（内建，有魔法）。** 加几根下划线 ≠ 有魔法，关键看是不是 Python 预定义的 dunder。

> [!warning]- 名字改写（mangling）只发生在类内部的双前缀
> ```python
> class A:
>     def __init__(self):
>         self.__x = 1          # 实际存成 self._A__x
> a = A()
> # a.__x        # ❌ AttributeError
> a._A__x        # 1  <- 被改写了
> ```
> 双前后缀的 dunder（`__x__`）**不**触发 mangling；只有"双前缀、无双后缀"才触发。

## 4. 实例一：读懂 `def _create(self, **kwargs)`（你代码里的真例）

一行同时用到"单前缀约定"和"`**` 收集"。

> [!success]- 拆解
> ```python
> class FakeLLM:
>     def _create(self, **kwargs):    # _ = 内部方法(约定)；**kwargs = 收集所有关键字
>         self.calls.append(kwargs)   # kwargs 是个 dict，原样存下

> - `_create` 前缀下划线：告诉读者"这是内部实现，外面通过 `.chat.completions.create` 间接调"。
> - `**kwargs`：`create(model=..., tools=...)` 的所有关键字被打包成 `{"model":..., "tools":...}`，测试再按 key 查。
> 关键：**`_` 只是提示，`**` 才是真干活的语法。** 两根符号各管一件事。

## 5. 实例二：`if __name__ == "__main__"` 与 dunder 的用途

`__name__` 是 Python 给每个模块设的 dunder：直接运行该文件时值为 `"__main__"`，被 import 时值为模块名。用来分"当脚本跑 vs 当库导入"。

> [!success]- 完整实现（webhook demo 就用了这个）
> ```python
> def main():
>     print("run demo")
>
> if __name__ == "__main__":   # 只有 python x.py 直接跑才进；import x 不进
>     main()
> ```
> 判断依据：`python webhook_demo.py` → `__name__ == "__main__"` → 跑 demo；`from webhook_demo import xxx` → `__name__ == "webhook_demo"` → 不跑，避免 import 时误触发。

## 7. 常见易错点

> [!warning]- 易错点
> - **调用处漏 `*`/`**`**：`f(mylist)` 是"传一个 list"，`f(*mylist)` 才是"把 list 摊成多个实参"。两回事。
> - **`**` 只能展开字符串键的 dict**：`f(**{1: "a"})` 报错，关键字实参名必须是合法标识符。
> - **把 `_x` 当"真私有"**：Python 没有强私有，`_x` 只是君子协定，外面照样能访问——别依赖它做安全边界。
> - **自造 dunder**：别定义 `__myattr__` 这种双前后缀名，那是 Python 的保留区，将来可能撞语义。
> - **`__x` 误以为"更私有"**：它触发名字改写、主要防子类覆盖，不是"更强的私有"，用多了反而难调试。
> - **`*args` 顺序**：定义里顺序必须是 `位置参数, *args, 关键字默认参数, **kwargs`，乱序语法错。

## 复杂度

> [!summary]- 说明
> 纯语法/约定，无算法复杂度。唯一实现层面：`*seq` / `**mapping` 展开是 $O(n)$ 拷贝成实参；`__x` mangling 在编译期完成，运行时零开销。

## 一句话总结

**`*`/`**` 的意思由"位置"决定（定义处收集、调用处展开、赋值处吞剩余）；下划线的意思由"是不是 dunder"决定——单/双前缀是你给的约定信号（无魔法），`__x__` 是 Python 定义的特殊名（有魔法，如 `__file__`/`__name__`）。**

## 模板归纳

看到符号先问"它在哪个位置"：
- 函数**定义**里的 `*`/`**` → 收集
- 函数**调用**里的 `*`/`**` → 展开
- **赋值**左边的 `*` → 吞剩余元素
- 名字**开头**单下划线 → 约定私有；名字**双前后缀** → Python 内建特殊名

```python
# 最小记忆模板
def f(a, *args, **kwargs):     # 定义：收集
    ...
f(*[1, 2], **{"k": 3})         # 调用：展开
first, *rest = [1, 2, 3]       # 赋值：吞剩余
_internal = ...                # 约定私有（无魔法）
__file__                       # Python 内建 dunder（有魔法）
```
