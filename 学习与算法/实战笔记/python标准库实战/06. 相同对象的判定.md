# Python 中 is 与相等性判断

> [!summary]- 速查
> 
> |写法|名称|作用|返回值|
> |---|---|---|---|
> |`x = 5`|assignment|把一个**名字**绑定到某个 object 上|无（statement，不是 expression）|
> |`x == y`|equality|比较两个 object 的**值**，调用 `__eq__`|`True` / `False`|
> |`x is y`|identity|比较是否**同一个 object**，等价于 `id(x) == id(y)`|`True` / `False`|
> 
> 一句话：问「这两个东西一样吗」用 `x == y`；问「这两个名字是不是同一个东西」用 `x is y`。
> 
> 实践中除了 `None`、`True` / `False` 和 sentinel，几乎不需要用 `is`。

> [!info]- 前提：赋值不是比较
> 
> 单个等号是 **assignment**（赋值），它做的是「把名字绑到 object 上」这个动作，本身不产生值，所以不能出现在需要 expression 的位置。
> 
> ```python
> x = 5          # ✅ statement
> if x = 5:      # ❌ SyntaxError，这里需要一个 expression
> if x == 5:     # ✅
> ```
> 
> 唯一容易混淆的例外是函数调用里的 keyword argument，那里的等号也不是比较：
> 
> ```python
> f(key=value)      # 传关键字参数
> f(key == value)   # 传一个 True/False 进去，完全不同的意思
> ```

> [!example]- 核心：值相等 vs 同一个对象
> 
> ```python
> a = [1, 2, 3]
> b = [1, 2, 3]      # 新建了另一个 list object
> c = a              # 只是给同一个 object 起了第二个名字（aliasing）
> 
> a == b   # True  —— 内容一样
> a is b   # False —— 内存里是两个不同的 object
> a == c   # True
> a is c   # True  —— 同一个 object
> ```
> 
> `is` 判断的是 aliasing，所以下面这个行为才说得通：
> 
> ```python
> c.append(4)
> print(a)   # [1, 2, 3, 4] —— a 和 c 本来就是同一个 object
> print(b)   # [1, 2, 3]
> ```
> 
> 想验证时直接看 `id()`：`a` 和 `c` 的 id 相同，`b` 不同。

> [!tip]- 使用场景：is 只用于 singleton
> 
> ```python
> if x is None:          # ✅ 标准写法
> if x is not None:      # ✅
> if flag is True:       # ⚠️ 能用但多余，直接 if flag: 就好
> if type(x) is list:    # ⚠️ 能用但推荐 isinstance(x, list)，能处理继承
> ```
> 
> `x is None` 成为惯例而不是 `x == None`，原因有两个：`None` 在整个进程里只有唯一一个 object，identity 判断更快；而 equality 可能被类重载。
> 
> ```python
> class Weird:
>     def __eq__(self, other):
>         return True
> 
> w = Weird()
> w == None    # True  ← 被骗了
> w is None    # False ← is 无法被重载，永远可靠
> ```
> 
> 另一个真实场景是 **sentinel object**，用来区分「没传参数」和「显式传了 None」：
> 
> ```python
> _MISSING = object()
> 
> def f(x=_MISSING):
>     if x is _MISSING:      # 只能用 is，_MISSING 没有有意义的「值」
>         print("没传参数")
>     elif x is None:
>         print("显式传了 None")
> ```
> 
> 除此之外的一切比较——数字、字符串、列表、自定义对象——都用 `x == y`。

> [!warning]- 三个必踩的坑
> 
> **坑一：小整数与短字符串的缓存，会让 `is` 看起来「能用」**
> 
> ```python
> a = 100
> b = 100
> a is b     # True  ← CPython 缓存了 -5 到 256 的 int object
> 
> a = 1000
> b = 1000
> a is b     # False（在交互式解释器里）← 超出缓存范围
> ```
> 
> 这是 CPython 的 implementation detail，不是语言保证。`if x is 100:` 可能今天能跑，换个值或换个解释器就挂。Python 3.8+ 遇到这种写法会直接给 `SyntaxWarning`。**数值比较永远用 `x == y`**。
> 
> **坑二：NaN 的反直觉行为**
> 
> ```python
> x = float('nan')
> x == x     # False ← IEEE 754 规定 NaN 不等于任何东西，包括自己
> x is x     # True  ← 但它确实是同一个 object
> ```
> 
> **坑三：把赋值写进需要 expression 的位置**
> 
> 三元表达式 `x if cond else y` 的两边必须都是 expression，statement 塞不进去：
> 
> ```python
> n = len(digits) if n != 0 else return []   # ❌ SyntaxError，return 是 statement
> 
> if not digits:                             # ✅ 拆成两行
>     return []
> n = len(digits)
> ```

## 模板归纳

判断该用哪个符号时，按这个顺序问自己：

1. **我是在「绑定名字」还是在「比较」？** 绑定用单个等号。绑定不产生值，所以它只能作为独立语句出现。
2. **比较的是「值」还是「身份」？** 绝大多数情况关心值 → `x == y`。
3. **只有当被比较的对象是 singleton 时才用 `is`。** 判据是：这个对象在进程中是否唯一，且「值」本身没有意义。满足的只有 `None`、`True` / `False`、`Ellipsis`，以及自己造的 sentinel。
4. **凡是依赖「两个字面量恰好是同一个 object」的写法，都是 bug。** 小整数缓存、字符串 interning 都属于 implementation detail，不能当作语义依据。

一个反向记忆点：`is` **无法被重载**，这既是它的优点（对抗恶意 `__eq__`），也是它的限制（对值语义完全无能为力）。
