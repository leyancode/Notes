
# Python import 搜索路径：sys.path 与 ModuleNotFoundError

`import X` 时 Python 只在 **`sys.path`（一串目录）** 里找 `X`，找不到就抛 `ModuleNotFoundError`。关键反直觉点：**`python 某脚本.py` 把"脚本所在目录"加进搜索路径，而不是你当前站的工作目录**——所以人在项目根、却导不到根目录下的包，是最高频的新手坑。

来源：task_011 调试时 `python tests/draft.py` 报 `No module named 'hpc_agent'`（2026-07-21）。

---

## 思路

import 不看"文件在硬盘哪"，只看 `sys.path` 这份"搜索目录清单"。清单从哪来、`sys.path[0]` 是谁，取决于**你用哪种方式启动**：

- `python path/to/script.py` → `sys.path[0]` = **脚本所在目录**（`path/to/`），**不含**当前工作目录（cwd）。
- `python -m pkg.mod` → `sys.path[0]` = **当前工作目录**（cwd）。
- 交互式 `python` REPL → `sys.path[0]` = cwd。

所以 `python tests/draft.py` 时，`tests/` 在路径上（`from fakes import` 能成），但项目根不在（`from hpc_agent import` 失败）。人站哪跟 import 无关——**import 认的是 `sys.path`，不是 cwd。**

> [!tip]- 核心思路
> 报 `ModuleNotFoundError` 先问一句：**这个包的父目录在 `sys.path` 里吗？**
>
> ```python
> import sys
> print(sys.path)     # 第一件事：打印看搜索了哪些目录
> ```
>
> 不变量：`python 文件.py` 只加"文件所在目录"，不加 cwd；`python -m` 才加 cwd。

---

## 1. 导入与创建

`sys` 是内置标准库，`import sys` 即可，无需安装。相关的还有 `PYTHONPATH` 环境变量。

> [!success]- 基础语法
> ```python
> import sys
> print(sys.path)                 # 当前的搜索路径清单（list[str]）
> print(sys.path[0])              # 谁排第一，取决于启动方式
> ```
> ```bash
> # 环境变量方式：把额外目录加进 sys.path（冒号分隔，. 表示当前目录）
> PYTHONPATH=. python tests/draft.py
> ```

---

## 2. 核心操作

| 操作 | 作用 | 注意事项 |
| --- | --- | --- |
| `python file.py` | 运行脚本 | `sys.path[0]` = 脚本目录，**不含 cwd** |
| `python -m pkg.mod` | 以模块方式运行 | `sys.path[0]` = **cwd**，能导 cwd 下的包 |
| `PYTHONPATH=. python ...` | 临时把当前目录加进路径 | `.` = cwd；多目录用 `:` 分隔 |
| `pip install -e .` | 可编辑安装本项目 | 一劳永逸让包全局可导（需 `pyproject.toml`/`setup.py`） |

> [!example]- 最小示例
> ```
> proj/
> ├─ hpc_agent/__init__.py
> └─ tests/draft.py     # 里面 import hpc_agent
> ```
> ```bash
> cd proj
> python tests/draft.py            # ❌ sys.path[0]=tests/，根不在 → ModuleNotFoundError
> PYTHONPATH=. python tests/draft.py   # ✅ 把根加进路径
> python -m tests.draft            # ✅ cwd(根) 进路径（但脚本内 import 要用 tests.fakes 全路径）
> ```

---

## 3. 关键行为与边界

> [!tip]- 为什么 pytest 不报这个错
> `pytest` 启动时会把 **rootdir（项目根）** 插进 `sys.path`，所以 `tests.fakes` 和 `hpc_agent` 都能导。这就是为什么正式测试写 `from tests.fakes import FakeLLM`（带 `tests.` 前缀）能跑，而你手写 `python tests/draft.py` 却不行——两种启动方式的 `sys.path` 不一样。

> [!warning]- 边界条件
> - **`__init__.py` 与包识别**：目录有 `__init__.py` 才是"标准包"；Python 3 也支持无 `__init__.py` 的"命名空间包"，但混用容易踩坑。`hpc_agent/` 有 `__init__.py`，`tests/` 没有。
> - **裸 import vs 全路径 import**：`from fakes import X`（裸）要求 `fakes.py` 的目录在 `sys.path`；`from tests.fakes import X`（全路径）要求 `tests` 的**父目录**在 `sys.path`。同一个文件两种写法对路径的要求不同。
> - **同名遮蔽**：若 cwd 有个 `json.py`，`import json` 可能导到你的文件而不是标准库——别拿标准库名给文件命名。
> - **`ModuleNotFoundError` vs `ImportError`**：前者是后者的子类，专指"整个模块没找到"；`from x import y` 里 `x` 在但 `y` 不在，报的是 `ImportError`。

## 4. 实例一：诊断一次 ModuleNotFoundError（本任务原型）

现象：`python tests/draft.py` 报 `No module named 'hpc_agent'`，但同文件里 `from fakes import` 却没事。

> [!success]- 完整实现
> ```python
> # 在报错脚本顶部临时插两行，看清搜索路径
> import sys
> print("sys.path[0] =", sys.path[0])   # tests/  <- 根源：根目录不在这
> print("has root? ", any(p.endswith("Analysis_Agent_Dev") for p in sys.path))
> from hpc_agent.llm_schema import TOOL_SCHEMAS   # 现在能解释为什么这行炸
> ```
> 判断逻辑：`fakes` 能导 = `tests/` 在路径上；`hpc_agent` 不能导 = 根不在路径上。**不对称正好定位问题**。修法：`PYTHONPATH=. python tests/draft.py`。

---

## 5. 实例二：写个"路径自愈"脚本头（草稿/一次性脚本常用）

有些一次性脚本想直接 `python x.py` 跑、又要导项目包，可以在脚本里把根目录动态塞进 `sys.path`。工程代码别滥用，但草稿很省事。

> [!success]- 完整实现
> ```python
> import sys
> from pathlib import Path
>
> # 把"本文件的上一级目录"（项目根）插到搜索路径最前
> ROOT = Path(__file__).resolve().parent.parent
> sys.path.insert(0, str(ROOT))
>
> from hpc_agent.llm_schema import TOOL_SCHEMAS   # 现在直接 python x.py 也能导
> print(len(TOOL_SCHEMAS))
> ```
> [!summary]- 当前实例复杂度
> - 时间/空间：$O(1)$，只是往 list 头插一个字符串。
> - 代价：把路径逻辑写进源码，可读性差；正式代码优先用 `-m` 或 `pip install -e .`。

---

## 6. 与相近写法怎么选

| 需求 | 推荐写法 | 原因 |
| --- | --- | --- |
| 临时跑个草稿 | `PYTHONPATH=. python x.py` | 零改动，最快 |
| 项目内正式运行模块 | `python -m pkg.mod` | 干净、cwd 自动进路径 |
| 反复开发、到处 import 本项目 | `pip install -e .` | 一次配置，永久可导 |
| 一次性脚本必须双击/直跑 | `sys.path.insert(...)` | 自包含，但污染源码，慎用 |

优先级：`-m` / `pip install -e .` > `PYTHONPATH=.` > 改 `sys.path`。

---

## 7. 常见易错点

> [!warning]- 易错点
> - **以为"人在根目录"就能导根下的包**：错。`python 文件.py` 加的是"文件所在目录"，不是 cwd。
> - **用标准库名命名文件**（`json.py`/`random.py`/`queue.py`）：会遮蔽标准库，导出诡异错误。
> - **`-m` 时还写裸 import**：`python -m tests.draft` 下 cwd 是根，`from fakes import` 会失败，得写 `from tests.fakes import`。启动方式变了，import 写法要跟着变。
> - **靠改 `sys.path` 掩盖结构问题**：能用 `-m`/可编辑安装就别硬插路径。
> - **忘了 `PYTHONPATH` 是冒号分隔**：`PYTHONPATH=.:src` 而不是逗号或空格。

---

## 复杂度

> [!summary]- 复杂度
> - import 查找：最坏 $O(P \cdot M)$，P 为 `sys.path` 目录数、M 为每目录查找成本；实际有缓存（`sys.modules`），重复 import 近 $O(1)$。
> - `sys.path.insert`：$O(1)$（list 头插是 $O(n)$ 严格说，但路径清单极短，可忽略）。

---

## 一句话总结

**`ModuleNotFoundError` 的本质是"包的父目录不在 `sys.path`"，而 `python 文件.py` 只把文件所在目录加进路径、不加你站的 cwd**——先 `print(sys.path)`，再用 `PYTHONPATH=.` 或 `python -m` 把根补进去。

## 模板归纳

看到以下信号时，想到 `sys.path` / 启动方式：
- `ModuleNotFoundError: No module named 'X'`，但 `X` 明明在项目里
- 同一脚本，有的 import 成、有的不成（不对称 = 路径线索）
- `pytest` 能跑但 `python 文件.py` 不能
- "我人明明在根目录了，为什么还导不到"

```python
# 诊断三连：报错先跑这个
import sys
print(sys.path[0])          # 谁是搜索起点
print(sys.path)             # 完整清单里有没有你要的包的父目录
# 修：PYTHONPATH=. python x.py   或   python -m pkg.mod
```
