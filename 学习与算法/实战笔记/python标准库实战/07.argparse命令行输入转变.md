# Python argparse：把命令行字符串变成校验过的 Namespace

shell 把用户敲的一整行切成字符串列表丢给 Python，`argparse` 用「**先登记规格、后一键解析**」接管校验、类型转换、默认值和 `-h` 帮助文本。凡是**脚本要收不止一两个命令行参数**、或**需要子命令**（`tool add` / `tool list`）时就该用它——核心认知是：`parse_args` 那一行是**分界线**，之前全是登记、什么都不发生，那一刻才真正干活。

来源：`hpc_agent/cli.py` 的 `build_parser()` / `main(argv=None)`（2026-07-25）。踩坑：把约束写进 `help=` 却没写 `choices=`；`--router` 的 `default` 复制粘贴成了 DB 路径，静默带病运行。

> [!info] 三遍复习路线
> 
> | 遍数 | 只看 | 目标 |
> | --- | --- | --- |
> | 第一遍 | 全篇 | 建立「登记期 / 解析期」这条分界线 |
> | 第二遍 | §2 核心操作 ★、§3 关键行为 ★、§6 weather 实例 ★、§8 易错点 ★ | 能默写上半张 API 表；能指着图说出套娃点和分界线 |
> | 第三遍（面试前） | 「一句话总结」+「自测问题」 | 十道题都能张口答 |
> 
> 标 ★ 的四节是必背；其余是查阅和练手。§2.1 是关键字参数速查，忘了就翻。

## 思路

不用它的问题：手动读 `sys.argv` 要自己判位置、自己转类型、自己写错误提示、自己维护 `-h` 文本，参数一多就是一坨 `if len(sys.argv) > 2`。

argparse 的做法是把这些全部前移到**登记期**：你先声明「有哪些参数、什么类型、白名单是什么、默认值多少」，`parse_args` 那一刻它按登记簿逐条匹配、转换、校验，非法输入在进入业务代码**之前**就被拦下（fail fast at the boundary）。代价是登记期完全不报错——写错的规格要到运行时才暴露。

> [!tip]- 核心思路
> 
> **一条对象链 + 一条分界线。**
> 
> 对象链：总管 `parser` → 子命令登记处 `subparsers` → 小 parser `ask_parser`，**每一环都要接住返回值**，因为下一步要对它调方法。
> 
> 分界线：`parse_args` 之前全是登记，那一刻才承接 shell 干活。
> 
> ```python
> parser  = argparse.ArgumentParser()              # ① 造总管
> sub     = parser.add_subparsers(dest="command")  # ② 开登记处
> ask     = sub.add_parser("ask")                  # ③ 登记子命令
> ask.add_argument("--db")                         # ④ 登记参数
> args    = parser.parse_args(argv)                # ⑤ ← 分界线在这一行
> ```
> 
> 不变量：解析只看**登记簿当时的状态**，所以所有 `add_*` 必须发生在 `parse_args` 之前。

## 1. 导入与创建

标准库自带，`import argparse` 即可，无需 `pip install`。所以你在自己项目里永远搜不到 `def add_argument` 的定义——它在 Python 安装目录里。

> [!success]- 基础语法（最小骨架）
> 
> ```python
> import argparse
> 
> parser = argparse.ArgumentParser(prog="tool", description="一句话说明")
> parser.add_argument("name")                      # 位置参数：必填、按位置
> parser.add_argument("--flag", default="x")       # 可选项：带 -- 前缀
> args = parser.parse_args()                       # 解析 → Namespace
> args.name, args.flag                             # 按属性取值
> ```
> 
> 登记什么名字，解析后就能 `args.那个名字` 取到：去掉 `--`，把 `-` 换成 `_`。

> [!tip]- 自己验证「这不是本地函数」
> 
> ```bash
> python -c "import argparse; help(argparse.ArgumentParser)"
> ```
> 
> 有官方文档说明它来自标准库；在项目目录里 `grep -rn "def add_argument"` 则一无所获。

## 2. 核心操作 ★

上半张表（位置参数 / 可选项 / `choices` / `default` / `type` / 子命令）是写任何 CLI 的日常操作，**必须能默写**；下半张表用到再查。

| 操作 | 作用 | 注意事项 |
| --- | --- | --- |
| `add_argument("name")` | 登记位置参数（默认必填、按位置） | 无 `--` 前缀 |
| `add_argument("--x")` | 登记可选项 | 属性名自动推导：`--dry-run` → `args.dry_run` |
| `action="store_true"` | 开关型选项，给了就是 `True` | `--verbose` 的标准写法，不接值 |
| `choices=[...]` | 白名单，**解析期**强制 | 非法值 → 打印 usage + `SystemExit(2)` |
| `default=...` | 不传时的值 | 过 `type`，不过 `choices`，见 §8 |
| `type=int` / `type=float` | 转换函数 | `int` 不带括号，传的是**函数本身** |
| `nargs="?"` / `"*"` / `"+"` / `2` | 收几个值 | 位置参数只要不是「恰好一个」就得用它 |
| `required=True`（用在 `--x` 上） | 可选项变必填 | 和 `add_subparsers(required=)` 是两码事 |
| `dest="name"` | 手动指定属性名 | `add_argument("--in", dest="input")` → `args.input` |
| `help="..."` | 帮助文本 | **纯文档，不执行任何约束** |
| `add_subparsers(dest="command")` | 开启子命令机制 | 用户选的子命令名记进 `args.command` |
| `add_parser("ask")` | 登记一个子命令 | 返回**小 ArgumentParser**（套娃点） |
| `parse_args(argv)` | 解析 | `argv=None` → 读真实 `sys.argv[1:]`；传列表 → 测试接缝 |

> [!note]- 还有这些，用到再查
> 
> | 操作 | 什么时候需要 |
> | --- | --- |
> | `parse_known_args()` | 要把认不出的参数原样转发给下游（包装 `mpirun`、`torchrun`）的逃生口 |
> | `add_argument_group("...")` | `-h` 里把参数分组，长 CLI 的可读性 |
> | `add_mutually_exclusive_group()` | `--json` 和 `--csv` 只能二选一 |
> | `action="append"` / `"count"` | `--tag a --tag b` 收成列表；`-vvv` 数次数 |
> | `type=Path` 或自定义函数 | 任何单参数可调用都能塞进 `type`，见 [[01. path]] |
> | `argparse.FileType("r")` | 直接把参数变成打开的文件对象——**它不会帮你关**，且新版 Python 已不推荐，优先 `type=Path` 自己 `open` |

> [!example]- 最小示例（实跑）
> 
> ```python
> import argparse
> p = argparse.ArgumentParser()
> p.add_argument("--dry-run", action="store_true")
> p.add_argument("--in", dest="input")
> print(p.parse_args(["--dry-run", "--in", "x"]))
> # Namespace(dry_run=True, input='x')   ← 短横变下划线；dest 覆盖推导
> ```

### 2.1 四个函数各自的常用参数

这四个函数的关键字参数最容易混：**同名的 `prog` / `help` / `required` / `dest` 在不同函数上含义并不相同**。分开记。

> [!note]- `ArgumentParser(...)`：造总管时配什么
> 
> | 参数 | 作用 | 备注 |
> | --- | --- | --- |
> | `prog="tool"` | **程序名**，只影响 `usage:` 和报错文案里显示的名字 | 不传就用 `os.path.basename(sys.argv[0])`——即脚本文件名。改名 / 打包成命令后想让提示对得上，就手动写死 |
> | `description="..."` | `-h` 里显示在 usage **下面**的一段说明 | 纯文档 |
> | `epilog="..."` | `-h` 里显示在**最末尾**的话 | 放「更多示例见 README」这类 |
> | `add_help=False` | 关掉自动的 `-h/--help` | **只有做 `parents=` 的公共父 parser 时才用**，见 §8 易错点六 |
> | `parents=[base]` | 继承另一个 parser 已登记的参数 | 抽公共选项（`--verbose` / `--config`）给多个子命令复用 |
> | `allow_abbrev=False` | 禁止选项缩写 | 默认 `True`，`--verb` 能匹配 `--verbose`；参数一多容易误匹配，严谨的 CLI 建议关掉 |
> | `formatter_class=...` | 改 `-h` 排版 | 常用 `argparse.RawTextHelpFormatter`（保留 help 里的换行） |
> 
> ```python
> p = argparse.ArgumentParser()
> p.prog          # 't5.py'  ← 不传 prog 时的默认值，就是脚本名
> ```

> [!note]- `add_argument(...)`：登记一条参数时配什么
> 
> | 参数 | 作用 | 最易踩的点 |
> | --- | --- | --- |
> | 第一个位置实参 | 无 `-` 前缀 → **位置参数**；有 `--` → **可选项** | 可以一次给多个写法：`add_argument("-v", "--verbose")`，属性名取**最长的那个** |
> | `dest="input"` | 手动指定存进 Namespace 的**属性名** | 只能用在可选项上。给位置参数传 `dest=` 直接 `ValueError: dest supplied twice for positional argument`——位置参数的名字本身就是 dest |
> | `type=int` | 转换函数，**解析期**调用 | 传函数本身、不带括号；转换失败要抛 `ValueError` / `argparse.ArgumentTypeError`，argparse 会翻译成 `SystemExit(2)` |
> | `default=` | 不传时的值 | 字符串 default 过 `type`，任何 default 都不过 `choices`（§8 易错点一） |
> | `choices=[...]` | 白名单 | 只查用户真传的值 |
> | `required=True` | 让**可选项**变必填 | 位置参数本来就必填，写了反而报错 |
> | `nargs=` | `"?"` 零或一 / `"*"` 零或多 / `"+"` 一或多 / 整数 N | `"+"` 收到的永远是 **list**，`"?"` 收到的是单个值 |
> | `action=` | `"store_true"` 开关 / `"count"` 数次数 / `"append"` 收成列表 / `"store_const"` 存固定值 / `"version"` 打印版本后退出 | 用了 `store_true` 就别再写 `type=bool`（`bool("False")` 是 `True`，坑） |
> | `metavar="CITY"` | 只改 `-h` 和 usage 里的**显示名**，**不改属性名** | 想改属性名要用 `dest=`。二者常被搞混 |
> | `help="..."` | 帮助文本 | 纯文档，不执行约束（§8 易错点三） |

> [!note]- `add_subparsers(...)`：开子命令登记处时配什么
> 
> | 参数 | 作用 | 备注 |
> | --- | --- | --- |
> | `dest="command"` | 把用户选的**子命令名**存进 `args.command` | 不写就无从判断用户选了哪个，报错信息也会变成没名字的一坨 |
> | `required=True` | 不给子命令就报错退出 | 默认是 `False`（裸跑会静默进到你的分发代码，`args.command` 是 `None`）。**建议永远写上** |
> | `title="子命令"` | `-h` 里这一组的标题 | 默认叫 `positional arguments` |
> | `metavar="COMMAND"` | 把 usage 里的 `{now,forecast,fc,history}` 换成一个干净的占位符 | 子命令一多，默认那串花括号会长到换行 |
> | `help="..."` | 这一组的整体说明 | 和每个 `add_parser(help=)` 是两回事 |
> 
> 一个 parser 只能调一次 `add_subparsers()`，第二次 `SystemExit(2)`。

> [!note]- `add_parser(...)`：登记一个子命令时配什么
> 
> | 参数 | 作用 | 备注 |
> | --- | --- | --- |
> | 第一个位置实参 | 子命令名，用户在 shell 里敲的就是它 | 也是存进 `args.<dest>` 的值 |
> | `help="查预报"` | 在**总管**的 `-h` 列表里，这一行显示什么 | 不写这个子命令就不出现在总览里 |
> | `aliases=["fc"]` | 别名，`weather fc` 等价于 `weather forecast` | `args.command` 存的是**用户实际敲的那个**（敲 `fc` 就是 `'fc'`），所以别用 `args.command` 做分发，用 `set_defaults(func=...)`（见 §6） |
> | `parents=[common]` | 继承公共父 parser 的参数 | 父 parser 必须 `add_help=False` |
> | `description=` / `epilog=` | 这个子命令自己 `-h` 的说明 | 和总管的互不影响 |

## 3. 关键行为与边界 ★

登记只是记账，`parse_args` 那一刻才逐条匹配、转换、查 `choices`、填 `default`。看懂下面两张图，argparse 就没有别的秘密了。

### 3.1 全链路：从敲回车到 `args.db`

> [!example]- 图一：shell → argv → Namespace
> 
> 数据只走这一条路，中间**没有任何一步在 Python 里**发生分词。
> 
> ```mermaid
> flowchart TD
>     U["用户敲的一整行命令"]
>     SH["shell 分词<br/>引号 · 转义 · 通配符展开 · 变量展开"]
>     K["内核 execve<br/>把切好的 argv 数组传给新进程"]
>     PY["Python 运行时<br/>sys.argv"]
>     AP["parse_args(sys.argv[1:])"]
>     NS["Namespace(command='ask', db='...')"]
>     U --> SH --> K --> PY --> AP --> NS
> ```
> 
> 三件事必须能指着图说出来：分词在 Python 之前、内核只负责传递、`sys.argv[0]` 是脚本名所以要切 `[1:]`。

> [!example]- 图二：对象链与分界线（写代码照这张）
> 
> ```mermaid
> flowchart TD
>     subgraph REG["登记期 —— 只记规格，什么都不发生"]
>         A["parser = argparse.ArgumentParser()<br/>类型 ArgumentParser（总管）"]
>         B["subparsers = parser.add_subparsers(dest='command')<br/>类型 _SubParsersAction（登记处）"]
>         C["ask_parser = subparsers.add_parser('ask')<br/>类型 ArgumentParser ← 套娃点"]
>         D["ask_parser.add_argument('--db')"]
>         A -->|add_subparsers| B
>         B -->|add_parser| C
>         C -->|add_argument| D
>     end
>     subgraph RUN["解析期 —— 唯一干活的一刻"]
>         E["args = parser.parse_args(argv)"]
>     end
>     subgraph USE["使用期"]
>         F["分发：判断 args.command 走哪个分支"]
>     end
>     D -.->|分界线| E
>     A -.->|同一个 parser| E
>     E --> F
> ```
> 
> `add_parser("ask")` 返回的是**又一个小 ArgumentParser**，所以 `ask_parser.add_argument(...)` 和 `parser.add_argument(...)` 是同一个类的同一个方法，没有任何新东西——这就是「套娃」。

> [!example]- 三个变量的真实类型（debug 时对得上号）
> 
> | 变量 | 真实类型 | 对它调的方法 |
> | --- | --- | --- |
> | `parser` | `ArgumentParser`（总管） | `add_argument` / `add_subparsers` / `parse_args` |
> | `subparsers` | `_SubParsersAction`（本质是个 Action） | `add_parser` |
> | `ask_parser` | `ArgumentParser`（分管一个子命令） | `add_argument` |
> 
> 报错信息里会直接出现 `_SubParsersAction`，别对不上号。

### 3.2 登记顺序：哪些自由、哪些是硬约束

> [!tip]- 三条规则（实跑验证过）
> 
> 1. 对象必须**先存在**，才能对它调方法；
> 2. 所有登记必须发生在 `parse_args` **之前**——解析只看登记簿当时的状态；
> 3. 唯一真正吃顺序的是**位置参数**：登记顺序 = 用户在 shell 里必须敲的顺序（靠位置匹配）。带 `--` 的可选项，登记顺序和敲的顺序都自由。

### 3.3 边界条件

> [!warning]- 边界条件
> 
> - **shell 不是操作系统，也不是「按空格切」**：切词是 shell（一个普通用户态程序）按引号 / 转义 / 通配符 / 变量展开规则干的。
>     - `python t.py "a b"` → Python 只收到**一个**参数
>     - `python t.py *.csv` → Python 收到的已是展开后的一堆文件名，**永远看不到那个 `*`**
>     - Windows 的 cmd 不做这件事，是 C 运行时或 Python 自己拆的。「shell 切词」是 Unix 语境的说法。
> - **拦截抛的是 `SystemExit(2)`，不是 `ValueError`**：argparse 打印 usage 后直接退出进程，业务代码根本跑不到。测试要写 `pytest.raises(SystemExit)`。
> - **内存状态不跨进程**：模块级的 list / dict 每次运行都重置，持久化必须落盘，见 §5。
> - **`add_subparsers()` 一个 parser 只能调一次**：第二次触发 `parser.error()`，打印 `error: cannot have multiple subparser arguments` 并 `SystemExit(2)`（**不是** `ArgumentError`）。
> - **调完 `add_subparsers()` 之后加的位置参数永远匹配不到**：子命令那个位置参数的 `nargs` 是 `PARSER`，会吞掉后面所有剩余参数。

## 4. 实例一：项目 cli.py 的骨架

输入是真实命令行，目标是「登记集中一处 + 入口可测试」。真实项目里 argparse 只占一个 `build_parser()` 函数加一行分发——重点在 `build_parser()` 与 `main(argv=None)` 的拆分。

> [!success]- 完整实现（节选自 `hpc_agent/cli.py`）
> 
> ```python
> import argparse
> 
> def build_parser():
>     parser = argparse.ArgumentParser(prog="hpc_agent", description="...")
>     subparsers = parser.add_subparsers(dest="command", required=True)
> 
>     ask_parser = subparsers.add_parser("ask", help="...")   # 小解析器
>     ask_parser.add_argument("question")                     # 位置参数
>     ask_parser.add_argument("--db", default=DEFAULT_DB_PATH)
>     ask_parser.add_argument("--router", choices=["rule", "llm"], default="rule")
>     return parser
> 
> def main(argv=None):                       # None = 真实命令行；列表 = 测试注入
>     args = build_parser().parse_args(argv)
>     if args.command == "ask":              # dest="command" 在这里兑现
>         ...
> 
> if __name__ == "__main__":
>     raise SystemExit(main())
> ```
> 
> 实跑结果：
> 
> ```python
> build_parser().parse_args(["ask", "100万规模下最快配置", "--router", "llm"])
> # Namespace(command='ask', question='100万规模下最快配置',
> #           db='data/benchmarks.sqlite', router='llm')   ← db 用了 default
> ```
> 
> 主流程：`build_parser` 只造规格不解析 → `main` 拿 `argv` 解析 → 按 `args.command` 分发。最易写错的位置：把 `parse_args()` 写死在 `build_parser` 里，测试就再也注入不进去了。

> [!tip]- 为什么 `argv=None` 是天然的测试接缝
> 
> `main(argv=None)` 和 `FakeLLM(client=None)` 是同款的「带默认值的可选注入」：生产走默认值读真实 `sys.argv`，测试传 `main(["ask", ...])` 离线跑。
> 
> 不需要 mock `sys.argv`，也不需要起子进程——这是 argparse 送的一个免费依赖注入点。

## 5. 实例二：50 行记账 CLI

一个能独立跑通的完整例子，顺带暴露「内存不跨进程」这个必踩的坑。例子本身是练手用的，真正要带走的是最后那条「进程与状态」的结论。

> [!success]- 完整实现（存成 `money.py`）
> 
> ```python
> """money.py —— 极简记账本"""
> import argparse
> 
> LEDGER = []
> 
> def build_parser():
>     parser = argparse.ArgumentParser(prog="money", description="记账本")
>     subparsers = parser.add_subparsers(dest="command", required=True)
> 
>     add_p = subparsers.add_parser("add", help="记一笔")
>     add_p.add_argument("item")
>     add_p.add_argument("amount", type=float)     # "abc" → 自动报错
>     add_p.add_argument("--tag", choices=["吃饭", "交通", "其他"], default="其他")
> 
>     subparsers.add_parser("total", help="看总额")
>     return parser
> 
> def main(argv=None):
>     args = build_parser().parse_args(argv)
>     if args.command == "add":
>         LEDGER.append((args.item, args.amount, args.tag))
>         print(f"记下: {args.item} {args.amount} [{args.tag}]")
>         return 0
>     if args.command == "total":
>         print(f"共 {len(LEDGER)} 笔, 合计 {sum(x[1] for x in LEDGER)}")
>         return 0
> 
> if __name__ == "__main__":
>     raise SystemExit(main())
> ```

> [!example]- 怎么跑（每行都实跑验证过）
> 
> ```bash
> python money.py add 早餐 -12.5 --tag 吃饭        # 正常记一笔
> python money.py --help                           # 自动生成的帮助
> python money.py total                            # 看总额
> 
> python money.py add 打车 -30 --tag 飞机          # choices 拦截，exit 2
> python money.py add 早餐 abc                     # type=float 拦截，exit 2
> python money.py                                  # required=True 拦截，exit 2
> ```
> 
> 最后三条被拦下不是程序坏了，是登记的规格在兑现。
> 
> 关于 `--` 的正确用法（见 §8 易错点五）：
> 
> ```bash
> python money.py add --tag 吃饭 早餐 -- -12.5     # 选项写在 -- 之前
> python money.py add 早餐 -- -12.5 --tag 吃饭     # 错！--tag 会被当位置参数
> ```

> [!warning]- 进程与状态：为什么 `total` 永远是 0 笔
> 
> 每次 `python money.py ...` 都是一个**全新进程**：`LEDGER = []` 重新执行，上一次 `add` 的数据随上一个进程一起死掉了。内存数据不跨进程存活。
> 
> 要让数据活下来必须写到磁盘，这正是真实项目用 SQLite 的原因：`import-csv` 进程写库、`ask` 进程读库，靠磁盘上的 `.sqlite` 文件接力。
> 
> 想在一次运行里验证 add → total，在测试或交互里连续调：
> 
> ```python
> main(["add", "早餐", "-12.5"]); main(["total"])   # 同一进程，LEDGER 还在
> ```

## 6. 实例三：weather CLI —— 多子命令的真实形状 ★

money.py 只够说明「子命令是什么」，真实 CLI 的形状是**多个子命令、各自带不同参数、还有一批公共选项**。这个例子把 §2.1 里的参数全用上一遍，并演示比 `if/elif` 更好的分发写法：`set_defaults(func=...)`。

> [!success]- 完整实现（存成 `weather.py`，可直接跑）
> 
> ```python
> """weather.py —— 假天气查询 CLI"""
> import argparse
> import datetime
> 
> FAKE = {"北京": 21, "上海": 25, "广州": 30}
> 
> def valid_date(s):
>     """自定义 type：转换失败要抛 ArgumentTypeError，argparse 会翻译成 exit 2"""
>     try:
>         return datetime.datetime.strptime(s, "%Y-%m-%d").date()
>     except ValueError:
>         raise argparse.ArgumentTypeError("日期要写成 YYYY-MM-DD，收到 %r" % s)
> 
> # ---- 三个子命令各自的处理函数：签名统一为 f(args) ----
> def cmd_now(args):
>     for city in args.cities:                       # nargs="+" 收到的是 list
>         print("[now] %s %s度 (verbose=%d)" % (city, FAKE.get(city, "?"), args.verbose))
>     return 0
> 
> def cmd_forecast(args):
>     print("[forecast] %s 未来 %d 天, 输出=%s" % (args.city, args.days, args.fmt))
>     return 0
> 
> def cmd_history(args):
>     print("[history] %s 从 %s 到 %s" % (args.city, args.start, args.end))
>     return 0
> 
> def build_parser():
>     # ---- 公共选项抽成 parent，三个子命令都继承 ----
>     common = argparse.ArgumentParser(add_help=False)      # add_help=False 必须！
>     common.add_argument("-v", "--verbose", action="count", default=0,
>                         help="啰嗦程度，可叠加 -vvv")
> 
>     parser = argparse.ArgumentParser(
>         prog="weather",                      # usage: 里显示的名字
>         description="查天气（演示用，数据是假的）",
>         epilog="更多示例见 README",           # -h 末尾那句
>     )
>     parser.add_argument("--version", action="version", version="weather 1.0")
> 
>     sub = parser.add_subparsers(
>         dest="command",
>         required=True,
>         title="子命令",                       # -h 里这一组的标题
>         metavar="COMMAND",                   # 免得 usage 里出现一长串 {now,fc,...}
>     )
> 
>     # now：nargs="+" 收多个城市
>     p_now = sub.add_parser("now", parents=[common], help="查当前天气")
>     p_now.add_argument("cities", nargs="+", metavar="CITY", help="一个或多个城市")
>     p_now.set_defaults(func=cmd_now)          # ← 把处理函数绑在这个子命令上
> 
>     # forecast：别名 + 互斥组（--json 和 --table 只能二选一）
>     p_fc = sub.add_parser("forecast", aliases=["fc"], parents=[common], help="查预报")
>     p_fc.add_argument("city")
>     p_fc.add_argument("-d", "--days", type=int, default=3, metavar="N")
>     g = p_fc.add_mutually_exclusive_group()
>     g.add_argument("--json",  dest="fmt", action="store_const", const="json")
>     g.add_argument("--table", dest="fmt", action="store_const", const="table")
>     p_fc.set_defaults(fmt="table", func=cmd_forecast)     # set_defaults 也能填普通默认值
> 
>     # history：自定义 type + 参数分组
>     p_hi = sub.add_parser("history", parents=[common], help="查历史")
>     p_hi.add_argument("city")
>     rng = p_hi.add_argument_group("时间范围")              # 只影响 -h 排版
>     rng.add_argument("--start", type=valid_date, required=True)
>     rng.add_argument("--end",   type=valid_date, default=datetime.date.today())
>     p_hi.set_defaults(func=cmd_history)
> 
>     return parser
> 
> def main(argv=None):
>     args = build_parser().parse_args(argv)
>     return args.func(args)            # ← 分发就这一行，没有 if/elif
> 
> if __name__ == "__main__":
>     raise SystemExit(main())
> ```
> 
> 主流程：`common` 造公共选项 → 总管配 `prog`/`description`/`--version` → `add_subparsers` 开登记处 → 三个 `add_parser` 各登记各的 → `set_defaults(func=)` 把函数**当默认值**塞进 Namespace → `main` 一行 `args.func(args)` 分发。
> 
> 最易写错的位置：`common` 忘了 `add_help=False`（见 §8 易错点六）、`set_defaults` 忘了写导致 `args.func` 不存在。

> [!tip]- 核心技巧：`set_defaults(func=...)` 替代 `if/elif` 分发
> 
> `set_defaults` 就是「往 Namespace 里预先塞一个键值对」，值是**任意对象**——包括函数。于是：
> 
> ```python
> p_now.set_defaults(func=cmd_now)     # 登记期：把函数焊在这个子命令上
> ...
> args.func(args)                      # 使用期：解析出哪个子命令，就自动调哪个函数
> ```
> 
> 三个好处：
> 
> 1. 加子命令**只改一处**（登记），不用回去补 `elif`；
> 2. `aliases` 天然生效——敲 `fc` 时 `args.command` 是 `'fc'` 而不是 `'forecast'`，用 `args.command` 判断会漏掉别名，用 `func` 不会；
> 3. 每个 `cmd_xxx(args)` 都是普通函数，可以脱开 argparse 单测。
> 
> 这和 `type=int` 传函数本身是同一件事：**函数是值，能存能传**，见 [[06.lamda|Python lambda]]。

> [!example]- 怎么跑（每行都实跑验证过）
> 
> ```bash
> python weather.py now 北京 上海 -vv          # [now] 北京 21度 (verbose=2) ... nargs="+" 收成 list
> python weather.py fc 北京 -d 7 --json        # [forecast] 北京 未来 7 天, 输出=json   ← 别名生效
> python weather.py forecast 北京              # 输出=table    ← set_defaults 填的默认值
> python weather.py history 北京 --start 2026-07-01   # --end 默认取今天
> python weather.py --version                  # weather 1.0，打印完直接退出
> 
> python weather.py history 北京 --start oops  # 自定义 type 拦截：日期要写成 YYYY-MM-DD
> python weather.py fc 北京 --json --table     # 互斥组拦截：--table: not allowed with --json
> python weather.py now                        # nargs="+" 至少要一个：required: CITY
> python weather.py                            # required=True 拦截：required: COMMAND
> ```
> 
> 后四条全是 `SystemExit(2)`，业务函数一次都没被调用——这就是 fail fast at the boundary。

> [!example]- 白送的 `-h`（实际输出，注意 title / metavar / epilog 落在哪）
> 
> ```text
> $ python weather.py -h
> usage: weather [-h] [--version] COMMAND ...      ← metavar="COMMAND" 的效果
> 
> 查天气（演示用，数据是假的）                        ← description
> 
> optional arguments:
>   -h, --help     show this help message and exit
>   --version      show program's version number and exit
> 
> 子命令:                                           ← title="子命令"
>   COMMAND
>     now          查当前天气                        ← add_parser(help=...)
>     forecast (fc)
>                  查预报                            ← aliases 显示在括号里
>     history      查历史
> 
> 更多示例见 README                                 ← epilog
> ```
> 
> ```text
> $ python weather.py history -h
> usage: weather history [-h] [-v] --start START [--end END] city
>                                                  ← prog 自动拼成「总管名 + 子命令名」
> positional arguments:
>   city
> 
> optional arguments:
>   -h, --help     show this help message and exit
>   -v, --verbose  啰嗦程度，可叠加 -vvv             ← parents=[common] 继承来的
> 
> 时间范围:                                          ← add_argument_group 的效果
>   --start START
>   --end END
> ```
> 
> 这一整页帮助文本，你一行都没写——它全是从登记簿自动生成的，这正是「先登记后解析」换来的回报。

> [!question]- 想自己改着玩，从这几处入手

## 7. 与相近写法怎么选

只保留会影响选择的差异，别的都不用记。

| 需求 | 推荐写法 | 原因 |
| --- | --- | --- |
| 标准库、无依赖的 CLI | `argparse` | 自带，够用；`-h` 白送 |
| 只有一两个参数的一次性脚本 | 直接读 `sys.argv` | argparse 反而重，登记比业务代码还长 |
| 大型 CLI，要补全、颜色、嵌套子命令 | `click` / `typer`（第三方） | 体验好，但引依赖 |
| 密钥类配置 | `os.environ` 环境变量 | 命令行参数会进 shell history，也会出现在 `ps` 输出里 |

## 8. 常见易错点 ★

argparse 的反直觉行为全部集中在三件事：**谁在什么时候被校验、拦下来时抛什么、登记顺序有没有约束**。

> [!warning]- 易错点一：`default` 过 `type`，不过 `choices`
> 
> 这条解释了「为什么有的 `default` 写错会被发现，有的不会」。
> 
> ```python
> p.add_argument("--n", type=int, default="5")              # args.n == 5，字符串 default 被转换了
> p.add_argument("--m", type=int, default="abc")            # 解析期直接报错 exit 2
> p.add_argument("--k", type=int, default=[])               # 非字符串，原样放行，不检查
> p.add_argument("--r", choices=["a","b"], default="zzz")   # 静默通过，choices 不查 default
> ```
> 
> 规则：**字符串 default 会走一遍 `type`；任何 default 都不走 `choices`。**
> 
> 所以复制粘贴错的 default（比如把 DB 路径抄进了 `--router`）会静默带病运行，直到下游炸。

> [!warning]- 易错点二：拦截抛的是 `SystemExit(2)`，不是 `ValueError`
> 
> argparse 拦下非法输入后打印 usage 并**直接退出进程**，业务代码根本跑不到。
> 
> 测试要写 `pytest.raises(SystemExit)`，写 `ValueError` 一定挂。
> 
> `required=True` 的 subparsers 不给子命令时同理：`error: the following arguments are required: command`——不是崩溃，是登记的规格在兑现。

> [!warning]- 易错点三：`help` 只是文档
> 
> 把约束写进 `help=` 而不写 `choices=`，等于**承诺了但不执行**。
> 
> `help` 给人看，`choices` 给机器执行。（本笔记的真实踩坑）

> [!warning]- 易错点四：总管上的可选项必须写在子命令之前
> 
> ```bash
> tool ask "问题" --verbose     # error: unrecognized arguments: --verbose
> tool --verbose ask "问题"     # 只有这样才行
> ```
> 
> 因为 `--verbose` 登记在**总管**上，而子命令后面的一切都被原封不动交给了小 parser——小 parser 从没听说过 `--verbose`。
> 
> 反过来，子命令自己的选项则必须写在子命令**之后**。

> [!warning]- 易错点五：以 `-` 开头的值（负数陷阱）
> 
> `money.py add 早餐 -12.5` 能跑通，但纯属**侥幸**：argparse 内部有个负数正则，且当前 parser 没有任何长得像负数的选项名时，才把这种参数当位置参数放行。
> 
> 实跑对照（`amount` 是位置参数）：
> 
> | 命令 | 无 `-1` 短选项 | 加了 `-1` 短选项 |
> | --- | --- | --- |
> | `add 早餐 -12.5` | OK | exit 2 |
> | `add 早餐 -1200` | OK | exit 2 |
> | `add 早餐 -12.5e3` | **exit 2** | exit 2 |
> 
> 注意报错文案是 `error: the following arguments are required: amount`——因为那个值被当成**选项**吃掉了，位置参数于是缺货，不是 `unrecognized arguments`。这个负数正则是 CPython 的内部实现细节，各版本会变，**别依赖它**。
> 
> 稳妥写法：用 `--` 显式分隔，但要记住 **`--` 之后的一切都是位置参数**，所以选项必须写在 `--` 前面：
> 
> ```bash
> python money.py add --tag 吃饭 早餐 -- -12.5     # ✅
> python money.py add 早餐 -- -12.5 --tag 吃饭     # ❌ unrecognized arguments: --tag 吃饭
> ```

> [!warning]- 易错点六：`parents=` 的父 parser 必须 `add_help=False`
> 
> 抽公共选项时最常见的翻车：
> 
> ```python
> base = argparse.ArgumentParser()                 # 默认 add_help=True，已经有 -h 了
> p    = argparse.ArgumentParser(parents=[base])   # 继承过来 → -h 撞车
> # ArgumentError: argument -h/--help: conflicting option strings: -h, --help
> ```
> 
> 父 parser 只是个「参数容器」，从不单独拿来解析，所以它不需要自己的 `-h`：
> 
> ```python
> base = argparse.ArgumentParser(add_help=False)   # ✅
> ```
> 
> 注意这条报的是 `ArgumentError`（登记期，真异常），不是 `SystemExit(2)`——因为出错的是**你的代码**，不是用户的输入。这也是区分两类错误的好例子：**用户的错 → usage + exit 2；程序员的错 → 抛异常**。

> [!warning]- 易错点七：`set_defaults` 和 `aliases` 的两个坑
> 
> - **忘了 `set_defaults(func=...)` 登记期不会报错**，要到 `args.func(args)` 那行才炸 `AttributeError: 'Namespace' object has no attribute 'func'`。登记期从不校验规格，这是 argparse 的通病。
> - **用 `args.command` 做分发会漏掉别名**：`add_parser("forecast", aliases=["fc"])` 时，用户敲 `fc`，`args.command` 存的就是 `'fc'` 而不是 `'forecast'`。所以一旦用了 `aliases`，分发必须走 `set_defaults(func=...)`（见 §6）。

> [!warning]- 易错点八：其他零碎
> 
> - 位置参数默认必填，但 `nargs="?"` / `nargs="*"` 的位置参数可以不给。
> - `type=int` 传的是 `int` **函数本身**（没括号），可塞任何单参数可调用——同 [[06.lamda|lambda]] 里「递工具不带括号」那条规则。
> - **别写 `type=bool`**：`bool("False")` 是 `True`，任何非空字符串都为真。开关一律用 `action="store_true"`。
> - `metavar=` 只改 `-h` 里的显示名，`dest=` 才改属性名，两者别搞混。
> - 属性名推导：`--dry-run` → `args.dry_run`；`add_argument("-v", "--verbose")` 取**最长**那个 → `args.verbose`。
> - 选项默认可缩写：`--verb` 能匹配上 `--verbose`。参数一多容易误匹配，严谨的 CLI 传 `allow_abbrev=False` 关掉。
> - `add_subparsers()` 一个 parser 只能调一次；调完之后再加的位置参数永远匹配不到。
> - `add_subparsers(required=)` 默认是 `False`，裸跑会静默进到分发代码、`args.command` 是 `None`。**建议永远显式写 `required=True`**。
> - 内存状态不跨进程：模块级列表 / 字典每次运行都重置，持久化必须落盘（见 §5）。

---

## 复杂度

> [!summary]- 复杂度
> 
> - **解析本身**：$O(n)$，$n$ 为 argv 的 token 数——每个 token 被消费一次；登记的参数条数是常量级小数字，实践中完全可忽略。
> - **真正的开销是启动**：`import argparse` 会连带拉起 `re` / `gettext` / `locale`。本机实测 `python -X importtime -c "import argparse"` 累计约 47 ms——对追求毫秒启动的 CLI 才需要在意，普通脚本不用管。
> - **额外空间**：$O(k)$，$k$ 为登记的参数条数（每条一个 Action 对象），加一个 Namespace。

---

## 一句话总结

**argparse = 一条对象链（总管 → 登记处 → 小 parser，环环接住返回值）加一条分界线（`parse_args` 之前全是登记，那一刻才承接 shell 干活）。** `--名字` 决定 `args.名字`；`choices` / `type` / `required` 在解析期拦非法输入并以 `SystemExit(2)` 退出；位置参数登记顺序就是用户敲的顺序；`argv=None` 是天然的测试接缝；内存状态不跨进程。

关键词：登记期 / 解析期、Namespace、套娃（subparser 也是 ArgumentParser）、fail fast at the boundary、`SystemExit(2)`、`argv=None`。

## 模板归纳

看到以下信号时，优先想到 argparse：

- 脚本要接收命令行参数，且**不止一两个**
- 需要**子命令**（`tool add` / `tool list`）
- 需要「非法参数在入口就被拦 + 自动 `-h` 帮助」
- 想让入口**可单测**（不起子进程、不 mock `sys.argv`）

```python
# 可直接复用的骨架
import argparse

def build_parser():
    p = argparse.ArgumentParser(prog="tool")
    p.add_argument("--verbose", action="store_true")   # 总管级选项要写在子命令前
    sub = p.add_subparsers(dest="command", required=True)

    one = sub.add_parser("run")
    one.add_argument("target")
    one.add_argument("--mode", choices=["a", "b"], default="a")
    return p

def main(argv=None):                 # None=真实命令行；列表=测试注入
    args = build_parser().parse_args(argv)
    if args.command == "run":
        ...

if __name__ == "__main__":
    raise SystemExit(main())
```

## 附录 A：零基础前置

模块 / 类 / 对象 / 方法四个词，是读懂正文的前提。已经懂的直接跳过——放在文末就是因为复习时每次都要跳过它。

> [!note]- 四个词
> 
> - **模块（module）**：别人写好的一份 Python 代码文件。标准库 = 装 Python 时自带的一批模块（`argparse`、`os`、`json`、`sqlite3`），不用 pip 装，`import` 就能用。所以在你的项目里永远搜不到它们的定义。
> - **类（class）**：图纸。
> - **对象（object）**：按图纸造出来的实体。`argparse.ArgumentParser(...)` 读法 = 去 `argparse` 模块里找到 `ArgumentParser` 这张图纸，加括号就是按图纸造一个对象。
> - **方法（method）**：长在对象身上的函数，用 `对象.方法()` 调。你早就用过：`mylist.append(3)`、`conn.execute(sql)`。
> 
> `argparse.ArgumentParser(prog="tool")` 和 `FakeLLM(client=None)` 完全同构：类加括号造对象，关键字参数配置它。
