# Python argparse

shell 把命令行切成字符串列表丢给 Python，argparse 用「先登记规格、后一键解析」接管校验、类型转换、默认值和帮助文本。

## 1. 一句话总结

argparse 是一条对象链加一条分界线。

> [!important]- 必须掌握
> 
> 这是整篇笔记的压缩版，第三遍复习只看这一节。 能把下面的核心结论完整复述出来，说明整个模型已经在脑子里。

> [!summary]- 核心结论
> 
> argparse = 一条对象链（总管 parser → 子命令登记处 → 小 parser，环环接住返回值）加一条分界线（`parse_args` 之前全是登记，那一刻才承接 shell 干活）。
> 
> `--名字` 决定 `args.名字`；`choices` / `type` / `required` 在解析期拦非法输入并以 `SystemExit(2)` 退出；位置参数登记顺序 = 用户敲的顺序；`argv=None` 是天然的测试接缝；内存状态不跨进程。

> [!note]- 关键词
> 
> 登记期 / 解析期、Namespace、套娃（subparser 也是 ArgumentParser）、fail fast at the boundary、`SystemExit(2)`、`argv=None`

## 2. 对象链与分界线
**图 A：谁是谁（从属关系，静态）**

```
argparse ──── 模块（Python 自带）
   │
   └── ArgumentParser ──── 类
         ├── .add_argument()    方法：登记一条参数
         ├── .add_subparsers()  方法：开子命令登记处
         └── .parse_args()      方法：解析
         （add_parser 不在这里——它是"登记处"对象的方法，
           但它返回的又是一个 ArgumentParser → 套娃）
```

**图 B：先干什么后干什么（生命周期，动态）——写代码照这张**

```
【登记期 —— 只记规格，什么都不发生】
 ① 造总管       parser = argparse.ArgumentParser()
 ② 开登记处     subparsers = parser.add_subparsers(dest="command")
 ③ 登记子命令   ask_parser = subparsers.add_parser("ask")
 ④ 登记参数     ask_parser.add_argument("--db")
────────────────────────────────────────────
【解析期 —— 唯一"干活"的一刻】
 ⑤ 承接 shell   args = parser.parse_args(argv)
────────────────────────────────────────────
【使用期】
 ⑥ 分发         if args.command == "ask": ...
```

每一环都要**接住返回值**（`subparsers = ...`、`ask_parser = ...`），因为下一步要对它调方法。

> [!tip]- 登记顺序的三条规则（②③④ 内部顺序自由，实跑验证过）
> 
> 1. 对象必须先存在，才能对它调方法；
> 2. 所有登记必须发生在 `parse_args` **之前**——解析只看登记簿当时的状态；
> 3. 唯一真正吃顺序的是**位置参数**：登记顺序 = 用户在 shell 里必须敲的顺序（位置参数靠位置匹配）。带 `--` 的可选项随意。
从 shell 到 `args.xxx`，数据只走这一条路。

```
shell 分词（引号/转义/通配符展开都在这一步）
   ↓  argv 数组，经内核 execve 传给新进程
sys.argv[1:]
   ↓
parser(ArgumentParser类型）──add_subparsers()──▶ _SubParsersAction    【登记期】
   │                                                 │                只记规格
   │                                       add_parser("ask")   什么都不发生
   │                                                 ↓
   │                                          ask_parser  ◀── 又一个 ArgumentParser    |                                                 |              （套娃点）
   │                                                 │
   │                                        add_argument("--db")
   │                                                 │
   └──────── parse_args(argv) ──-────────────────────┘  【解析期】
                 ↓                                       唯一干活的一刻
             Namespace(command='ask', db='...')
                 ↓                                       【使用期】
             if args.command == "ask": ...
```

> [!important]- 必须掌握
> 
> 看懂这张图，argparse 就没有别的秘密了。 三件事必须能指着图说出来：套娃点在哪、每个方法长在谁身上、分界线在哪一行。

> [!summary]- 核心结论
> 
> `add_parser("ask")` 返回的是又一个小 ArgumentParser，所以 `ask_parser.add_argument(...)` 和 `parser.add_argument(...)` 是同一个类的同一个方法，没有任何新东西。
> 
> 每一环都必须接住返回值（`subparsers = ...`、`ask_parser = ...`），因为下一步要对它调方法。

> [!example]- 三个变量分别是什么
> 
> |变量|真实类型|对它调的方法|
> |---|---|---|
> |`parser`|`ArgumentParser`（总管）|`add_argument` / `add_subparsers` / `parse_args`|
> |`subparsers`|`_SubParsersAction`（本质是个 Action）|`add_parser`|
> |`ask_parser`|`ArgumentParser`（分管一个子命令）|`add_argument`|
> 
> debug 时报错信息里会直接出现 `_SubParsersAction`，看到别对不上号。

> [!warning]- 常见误区：交接点的两个错误说法
> 
> shell 不是操作系统。切词是 shell（一个普通用户态程序）干的，内核只负责把切好的 argv 数组通过 `execve` 传给新进程。链条是 shell → 内核 → Python 运行时 → `sys.argv`。
> 
> 也不是「按空格切」，而是按 shell 的分词规则：引号、转义、通配符展开、变量展开全部发生在 Python 之前。
> 
> - `python t.py "a b"` → Python 只收到一个参数
> - `python t.py *.csv` → Python 收到的已经是展开后的一堆文件名，永远看不到那个 `*`
> 
> Windows 的 cmd 不做这件事，是 C 运行时或 Python 自己拆的。「shell 切词」是 Unix 语境的说法。

> [!tip]- 自己验证「这不是本地函数」
> 
> ```bash
> python -c "import argparse; help(argparse.ArgumentParser)"   # 有官方文档
> grep -rn "def add_argument" 你的项目/                         # 搜不到
> ```
> 
> 定义在 Python 安装目录里，不在项目里。

## 3. 核心 API 表

登记什么名字，解析后就能 `args.那个名字` 取到（`--` 去掉，`-` 换 `_`）。

> [!important]- 必须掌握
> 
> 上半张表（位置参数 / 可选项 / choices / default / type / 子命令）是写任何 CLI 的日常操作，必须能默写。 下半张表用到再查即可。

> [!example]- 常用操作
> 
> |操作|作用|注意事项|
> |---|---|---|
> |`add_argument("name")`|登记位置参数（默认必填、按位置）|无 `--` 前缀|
> |`add_argument("--x")`|登记可选项|属性名自动推导：`--dry-run` → `args.dry_run`|
> |`action="store_true"`|开关型选项，给了就是 `True`|`--verbose` 的标准写法，不接值|
> |`choices=[...]`|白名单，解析期强制|非法值 → 打印 usage + `SystemExit(2)`|
> |`default=...`|不传时的值|过 `type`，不过 `choices`，见 §4|
> |`type=int` / `type=float`|转换函数|`int` 不带括号，传的是函数本身|
> |`nargs="?"` / `"*"` / `"+"` / `2`|收几个值|位置参数只要不是「恰好一个」就得用它|
> |`required=True`（用在 `--x` 上）|可选项变必填|和 subparsers 的 `required` 是两码事|
> |`dest="name"`|手动指定属性名|`add_argument("--in", dest="input")` → `args.input`|
> |`help="..."`|帮助文本|纯文档，不执行任何约束|
> |`add_subparsers(dest="command")`|开启子命令机制|用户选的子命令名记进 `args.command`|
> |`add_parser("ask")`|登记一个子命令|返回小 ArgumentParser（套娃点）|
> |`parse_args(argv)`|解析|`argv=None` → 读真实 `sys.argv[1:]`；传列表 → 测试接缝|

> [!note]- 还有这些，用到再查
> 
> |操作|什么时候需要|
> |---|---|
> |`parse_known_args()`|要把认不出的参数原样转发给下游（包装 `mpirun`、`torchrun`）的逃生口|
> |`add_argument_group("...")`|`-h` 里把参数分组，长 CLI 的可读性|
> |`add_mutually_exclusive_group()`|`--json` 和 `--csv` 只能二选一|
> |`action="append"` / `"count"`|`--tag a --tag b` 收成列表；`-vvv` 数次数|
> |`type=Path` 或自定义函数|任何单参数可调用都能塞进 `type`|
> |`argparse.FileType("r")`|直接把参数变成打开的文件对象（注意它不会帮你关）|

> [!tip]- 最小骨架
> 
> ```python
> import argparse
> 
> parser = argparse.ArgumentParser(prog="tool", description="一句话说明")
> parser.add_argument("name")                      # 位置参数
> parser.add_argument("--flag", default="x")       # 可选项
> args = parser.parse_args()                       # 解析 → Namespace
> args.name, args.flag                             # 按属性取
> ```

## 4. 关键行为与易错点

登记只是记账，`parse_args` 那一刻才逐条匹配、转换、查 choices、填 default。

> [!important]- 必须掌握
> 
> 这一节是全篇踩坑密度最高的地方。 argparse 的反直觉行为全部集中在三件事：谁在什么时候被校验、拦下来时抛什么、登记顺序有没有约束。

> [!question]- 为什么要「先登记后解析」
> 
> 规格集中一处声明，`-h` 自动生成，非法输入在进入业务代码之前就被拦下（fail fast at the boundary）。
> 
> 代价是：登记期完全不报错，写错的规格要到运行时才暴露。

> [!warning]- 易错点一：default 过 type，不过 choices
> 
> 这条解释了「为什么有的 default 写错会被发现，有的不会」。
> 
> ```python
> p.add_argument("--n", type=int, default="5")     # args.n == 5，字符串 default 被转换了
> p.add_argument("--m", type=int, default="abc")   # 解析期直接报错
> p.add_argument("--k", type=int, default=[])      # 非字符串，原样放行，不检查
> p.add_argument("--r", choices=["a","b"], default="zzz")   # 静默通过，choices 不查 default
> ```
> 
> 规则：字符串 default 会走一遍 `type`；任何 default 都不走 `choices`。
> 
> 所以复制粘贴错的 default（比如把 DB 路径抄进了 `--router`）会静默带病运行，直到下游炸。

> [!warning]- 易错点二：拦截抛的是 SystemExit(2)，不是 ValueError
> 
> argparse 拦下非法输入后打印 usage 并直接退出进程，业务代码根本跑不到。
> 
> 测试要写 `pytest.raises(SystemExit)`，写 `ValueError` 一定挂。
> 
> `required=True` 的 subparsers 不给子命令时同理：`error: the following arguments are required: command` 不是崩溃，是登记的规格在兑现。

> [!warning]- 易错点三：help 只是文档
> 
> 把约束写进 `help=` 而不写 `choices=`，等于承诺了但不执行。
> 
> help 给人看，choices 给机器执行。

> [!warning]- 易错点四：登记顺序哪些自由、哪些是硬约束
> 
> - 可选项（带 `--`）：登记顺序自由，用户敲的顺序也自由。
> - 位置参数：登记顺序 = 用户在 shell 里必须敲的顺序，靠位置匹配，硬约束。
> - `add_subparsers()` 一个 parser 只能调一次，第二次抛 `ArgumentError: cannot have multiple subparser arguments`。
> - 调完 `add_subparsers()` 之后不能再加位置参数：子命令那个位置参数的 `nargs` 是 `PARSER`，会吞掉后面所有剩余参数，后加的位置参数永远匹配不到。
> - 总管上的可选项必须写在子命令之前：
> 
> ```bash
> tool ask "问题" --verbose     # error: unrecognized arguments: --verbose
> tool --verbose ask "问题"     # 只有这样才行
> ```
> 
> 因为 `--verbose` 登记在总管上，而子命令后面的一切都被原封不动交给了小 parser。

> [!warning]- 易错点五：以 - 开头的值（负数陷阱）
> 
> `money.py add 早餐 -12.5` 能跑通，但纯属侥幸。
> 
> argparse 内部有个负数正则 `^-\d+$|^-\d*\.\d+$`，且当前 parser 没有任何长得像负数的选项名时，才把这种参数当位置参数放行。
> 
> 一旦加了 `-1` 这样的短选项，或值写成 `-12.5e3`、`-1,200`，立刻变成 `error: unrecognized arguments`。
> 
> 稳妥写法：
> 
> ```bash
> python money.py add 早餐 -- -12.5     # -- 之后一律当位置参数
> ```

> [!warning]- 易错点六：其他零碎
> 
> - 位置参数默认必填，但 `nargs="?"` / `nargs="*"` 的位置参数可以不给。
> - `type=int` 传的是 `int` 函数本身（没括号），可塞任何单参数可调用。
> - 属性名推导：`--dry-run` → `args.dry_run`；想改名用 `dest=`。
> - 内存状态不跨进程：模块级列表或字典每次运行都重置，持久化必须落盘（见 §6）。

## 5. 实例一：项目 cli.py 的骨架

真实项目里 argparse 只占一个 `build_parser()` 函数加一行分发。

> [!info]- 需要掌握
> 
> 这是可以直接抄的工程模板。 重点在 `build_parser()` 与 `main(argv=None)` 的拆分，它同时解决了「可测试」和「入口清晰」两件事。

> [!example]- 结构（节选自 hpc_agent/cli.py）
> 
> ```python
> def build_parser():
>     parser = argparse.ArgumentParser(prog="hpc_agent", description="...")
>     subparsers = parser.add_subparsers(dest="command", required=True)
> 
>     ask_parser = subparsers.add_parser("ask", help="...")   # 小解析器
>     ask_parser.add_argument("question")                     # 位置参数
>     ask_parser.add_argument("--db", default=DEFAULT_DB_PATH)
>     ask_parser.add_argument("--router", choices=["rule", "llm"], default="rule")
>     return parser
> 
> def main(argv=None):                       # None = 真实命令行；列表 = 测试注入
>     args = build_parser().parse_args(argv)
>     if args.command == "ask":              # dest="command" 在这里兑现
>         ...
> 
> if __name__ == "__main__":
>     raise SystemExit(main())
> ```
> 
> 实跑结果：
> 
> ```python
> build_parser().parse_args(["ask", "100万规模下最快配置", "--router", "llm"])
> # Namespace(command='ask', question='100万规模下最快配置',
> #           db='data/benchmarks.sqlite', router='llm')   ← db 用了 default
> ```

> [!tip]- argv=None 是天然的测试接缝
> 
> `main(argv=None)` 和 `client=None` 是同款的「带默认值的可选注入」：生产读真实 `sys.argv`，测试传 `main(["ask", ...])` 离线跑。
> 
> 不需要 mock `sys.argv`，也不需要起子进程。详见 [[testing-doubles-and-di]]。

## 6. 实例二：50 行记账 CLI

一个能独立跑通的完整例子，顺带暴露「内存不跨进程」这个必踩的坑。

> [!info]- 需要掌握
> 
> 例子本身是练手用的。 真正要带走的是最后那条「进程与状态」的结论，它解释了为什么真实项目必须上 SQLite 或文件。

> [!example]- 完整实现（存成 money.py）
> 
> ```python
> """money.py —— 极简记账本"""
> import argparse
> 
> LEDGER = []
> 
> def build_parser():
>     parser = argparse.ArgumentParser(prog="money", description="记账本")
>     subparsers = parser.add_subparsers(dest="command", required=True)
> 
>     add_p = subparsers.add_parser("add", help="记一笔")
>     add_p.add_argument("item")
>     add_p.add_argument("amount", type=float)     # "abc" → 自动报错
>     add_p.add_argument("--tag", choices=["吃饭", "交通", "其他"], default="其他")
> 
>     subparsers.add_parser("total", help="看总额")
>     return parser
> 
> def main(argv=None):
>     args = build_parser().parse_args(argv)
>     if args.command == "add":
>         LEDGER.append((args.item, args.amount, args.tag))
>         print(f"记下: {args.item} {args.amount} [{args.tag}]")
>         return 0
>     if args.command == "total":
>         print(f"共 {len(LEDGER)} 笔, 合计 {sum(x[1] for x in LEDGER)}")
>         return 0
> 
> if __name__ == "__main__":
>     raise SystemExit(main())
> ```

> [!example]- 怎么跑
> 
> ```bash
> python money.py add 早餐 -- -12.5 --tag 吃饭   # 正常记一笔（-- 防负数陷阱）
> python money.py total                          # 看总额
> python money.py -h                             # 自动生成的帮助
> python money.py add 打车 -30 --tag 飞机        # choices 拦截，exit 2
> python money.py add 早餐 abc                   # type=float 拦截
> python money.py                                # required=True 拦截，这是正确行为
> ```
> 
> 最后一条：裸跑被拦下不是程序坏了，是登记的规格在兑现。

> [!warning]- 进程与状态：为什么 total 永远是 0 笔
> 
> 每次 `python money.py ...` 都是一个全新进程：`LEDGER = []` 重新执行，上一次 add 的数据随上一个进程一起死掉了。内存数据不跨进程存活。
> 
> 要让数据活下来必须写到磁盘，这正是真实项目用 SQLite 的原因：`import-csv` 进程写库、`ask` 进程读库，靠磁盘上的 `.sqlite` 文件接力。
> 
> 想在一次运行里验证 add → total，在测试或交互里连续调：
> 
> ```python
> main(["add", "早餐", "-12.5"]); main(["total"])   # 同一进程，LEDGER 还在
> ```

## 7. 与相近写法怎么选

标准库够用就别引依赖。

> [!info]- 需要掌握
> 
> 选型题，面试或 code review 里会被问「为什么不用 click」。 记住每行的「原因」列即可。

> [!example]- 选型表
> 
> |需求|推荐写法|原因|
> |---|---|---|
> |标准库、无依赖的 CLI|`argparse`|自带，够用|
> |只有一两个参数的一次性脚本|直接读 `sys.argv`|argparse 反而重|
> |大型 CLI，要补全、颜色、嵌套子命令|`click` / `typer`（第三方）|体验好，但引依赖|
> |密钥类配置|`os.environ` 环境变量|命令行参数会进 shell history，也会出现在 `ps` 里|

## 8. 模板归纳

看到这三个信号，优先想到 argparse。

> [!info]- 需要掌握
> 
> 信号识别加一份可直接复制的骨架。 写新 CLI 时从这里起步。

> [!note]- 触发信号
> 
> - 脚本要接收命令行参数，且不止一两个
> - 需要子命令（`tool add` / `tool list`）
> - 需要「非法参数在入口就被拦 + 自动 `-h` 帮助」

> [!example]- 可复制骨架
> 
> ```python
> import argparse
> 
> def build_parser():
>     p = argparse.ArgumentParser(prog="tool")
>     p.add_argument("--verbose", action="store_true")   # 总管级选项要写在子命令前
>     sub = p.add_subparsers(dest="command", required=True)
> 
>     one = sub.add_parser("run")
>     one.add_argument("target")
>     one.add_argument("--mode", choices=["a", "b"], default="a")
>     return p
> 
> def main(argv=None):
>     args = build_parser().parse_args(argv)
>     if args.command == "run":
>         ...
> 
> if __name__ == "__main__":
>     raise SystemExit(main())
> ```

>

## 附录 A：零基础前置

模块 / 类 / 对象 / 方法四个词，是读懂正文的前提。

> [!note]- 了解即可
> 
> 已经懂的直接跳过。 放在文末是因为复习时每次都要跳过它。

> [!example]- 四个词
> 
> - 模块（module）：别人写好的一份 Python 代码文件。标准库 = 装 Python 时自带的一批模块（`argparse`、`os`、`json`、`sqlite3`），不用 pip 装，`import` 就能用。所以在你的项目里永远搜不到它们的定义，定义在 Python 安装目录里。
> - 类（class）：图纸。
> - 对象（object）：按图纸造出来的实体。`argparse.ArgumentParser(...)` 读法 = 去 `argparse` 模块里找到 `ArgumentParser` 这张图纸，加括号就是按图纸造一个对象。
> - 方法（method）：长在对象身上的函数，用 `对象.方法()` 调。你早就用过：`mylist.append(3)`、`conn.execute(sql)`。
> 
> `argparse.ArgumentParser(prog="tool")` 和 `FakeLLM(client=None)` 完全同构：类加括号造对象，关键字参数配置它。
