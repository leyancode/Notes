# Python `*` 与 `**`：同一个符号，两个相反的方向

`*` 和 `**` 解决的问题是：**函数的参数个数事先不知道**。要么"我不知道调用方会给几个"（收集），要么"我手里有一堆现成的值，想一次性喂进去"（展开）。写任何包装函数、转发函数、装饰器都绕不开。

---

## 思路（整份笔记只有这一句是必须先记住的）

**同一个符号，看它长在哪，意思正好相反：**

| 长在哪 | 干什么 | 方向 |
|---|---|---|
| **`def` 的形参表里** | 把散着的实参**收集**成一个容器 | 多 → 一 |
| **调用的括号里** | 把一个容器**拆开**成散的实参 | 一 → 多 |
| **字面量里**（`[...]` `{...}`） | 把一个容器**倒进**另一个容器 | 一 → 一（合并） |

> [!tip]- 核心思路
> **`*` 管位置参数（→ tuple），$* *$ 管关键字参数（→ dict）。**
>
> ```python
> def f(*args, **kwargs):     # 收集：调用方给的散装实参被打包
>     print(args, kwargs)
>
> f(1, 2, a=3)                # (1, 2) {'a': 3}
>
> nums = [1, 2]
> opts = {"a": 3}
> f(*nums, **opts)            # 展开：容器被拆散再喂进去 → 结果同上
> ```
>
> 判断依据：**问自己"此刻我是在造一个函数，还是在调一个函数？"** 造函数（def）→ 收集；调函数 → 展开。

**你一直搞混的那个点**：`def emit(self, event, **payload)` 写完之后，函数体里的 `payload` **就是一个普通 dict**了。`**` 在 def 那一行**已经用掉了**，它不会跟着 `payload` 这个名字走。之后你想再用 `**`，是一次**全新的**决定：是要拆开喂给别的函数，还是要倒进一个新 dict。

## 0. 地基：位置参数 vs 关键字参数

不分清这个，后面全是浆糊。

> [!info]- 两种传参方式
> ```python
> def book(hotel, nights):
>     return f"{hotel} 住 {nights} 晚"
>
> book("如家", 3)                  # 位置传参：靠顺序对号入座
> book(hotel="如家", nights=3)     # 关键字传参：靠名字对号入座
> book("如家", nights=3)           # 混用：位置的必须在前面
>
> book(nights=3, "如家")           # ❌ SyntaxError: positional argument follows keyword argument
> ```
>
> **术语**（面试会用到，别说错）：
> - **形参 parameter** = `def` 那行括号里的名字（`hotel`、`nights`），是"坑位"
> - **实参 argument** = 调用时真正传进去的值（`"如家"`、`3`），是"填进坑的东西"

**记住这条对应关系，后面全靠它**：

```
*  ←→ 位置参数 ←→ tuple  （有序、无名）
** ←→ 关键字参数 ←→ dict （有名、成对）
```

---

## 1. `*args`：收集多余的**位置**参数

> [!success]- 基本行为
> ```python
> def total(*args):
>     print(type(args), args)
>     return sum(args)
>
> total(1, 2, 3)      # <class 'tuple'> (1, 2, 3)  → 6
> total(5)            # <class 'tuple'> (5,)       → 5
> total()             # <class 'tuple'> ()         → 0
> ```
>
> **三个特性**：
> 1. 收到的是 **tuple**，不是 list（不可变——防止你在函数里改了它，调用方却看不出来）
> 2. 一个都没给时是**空 tuple `()`**，不是 `None`——所以 `for x in args` 永远安全，不用判空
> 3. `args` 只是**惯例名**，`*rest`、`*values` 都合法。**起作用的是那个 `*`**

### 和固定形参一起用

```python
def order(customer, *items):
    return f"{customer} 点了 {len(items)} 样：{items}"

order("张三", "牛肉面", "凉菜")     # 张三 点了 2 样：('牛肉面', '凉菜')
order("张三")                      # 张三 点了 0 样：()
```

`customer` 先吃掉第一个位置参数，**剩下的全归 `*items`**。所以 `*args` 之后不能再有普通位置参数——它把后面的全吞了。

---

## 2. `**kwargs`：收集多余的**关键字**参数

> [!success]- 基本行为
> ```python
> def config(**kwargs):
>     print(type(kwargs), kwargs)
>
> config(host="localhost", port=8080)
> # <class 'dict'> {'host': 'localhost', 'port': 8080}
>
> config()
> # <class 'dict'> {}          ← 空 dict，不是 None
> ```
>
> **三个特性**：
> 1. 收到的是 **dict**，键是**字符串**（形参名），值是传进来的东西
> 2. **保留传入顺序**（Python 3.7+ dict 有序）
> 3. **手写**调用时，键必须是合法标识符（`config(2fast=1)` 是 SyntaxError）；但用 `**` 展开一个现成 dict 时只要求键是**字符串**——细节见 §8 陷阱 6

### 完整的形参顺序（背下来）

```python
def full(a, b=2, *args, c, d=4, **kwargs):
    ...
#      ↑  ↑     ↑      ↑  ↑     ↑
#      │  │     │      │  │     └ 收集剩下的关键字参数
#      │  │     │      │  └ 有默认值的 keyword-only
#      │  │     │      └ 【必填】keyword-only：在 *args 后面，只能用名字传
#      │  │     └ 收集剩下的位置参数
#      │  └ 有默认值的普通参数
#      └ 普通位置参数
```

**顺序是固定的**：普通 → `*args` → keyword-only → `**kwargs`。写反了直接 SyntaxError。

## 3. 调用处的 `*` / `**`：把容器拆开

**这是你写 `open(**payload)` 时用到的那个语义。**

> [!success]- 展开的本质是"改写调用"
> ```python
> def ship(carrier, weight):
>     return f"{carrier} 承运 {weight}kg"
>
> args = ["顺丰", 2.5]
> ship(*args)                       # 等价于 ship("顺丰", 2.5)
>
> opts = {"carrier": "顺丰", "weight": 2.5}
> ship(**opts)                      # 等价于 ship(carrier="顺丰", weight=2.5)
> ```
>
> **关键**：展开之后，dict 的**键必须能对上被调函数的形参名**。键是给**对方的坑位**用的，不是随便什么数据都能这么传。

### ⚠️ 键对不上的三种炸法

```python
ship(**{"收件人": "张三"}) # 这里只接受关键字，不要考虑位置
# TypeError: ship() got an unexpected keyword argument '收件人'    ← 多了对方不认识的

ship(**{"carrier": "顺丰"})
# TypeError: ship() missing 1 required positional argument: 'weight'  ← 少了对方要的

ship("顺丰", **{"carrier": "中通", "weight": 2.5})
# TypeError: ship() got multiple values for argument 'carrier'     ← 一个坑填了两次
```

> [!danger]- 你踩的就是第二种
> ```python
> payload = {"args": {"db_path": "/home/user/b.sqlite"}}
> open(**payload, encoding="utf-8")
> # TypeError: open() missing required argument 'file' (pos 1)
> ```
> 它被改写成了 `open(args={...}, encoding="utf-8")`：`open` 没有 `args` 这个形参，而它真正要的 `file` 没人填。
>
> **根因**：`payload` 是**要被记录的数据**，不是**给 open 的参数**。数据和参数长得都像 dict，但用途完全不同——**用 `**` 展开之前先问：这个 dict 的键，是不是对方形参的名字？**

### 可以展开什么

```python
ship(*("顺丰", 2.5))        # tuple ✅
ship(*["顺丰", 2.5])        # list ✅
ship(*"ab")                 # 字符串也是可迭代的！→ ship("a", "b")
ship(**{"carrier": "顺丰", "weight": 2.5})   # dict ✅

# ** 的键必须是字符串
ship(**{1: "顺丰"})         # TypeError: keywords must be strings
```

### 混用与顺序

```python
def f(a, b, c, d):
    return (a, b, c, d)

f(*[1, 2], **{"c": 3, "d": 4})     # (1, 2, 3, 4)
f(1, *[2], c=3, **{"d": 4})        # (1, 2, 3, 4)  ← 可以混得很花
```

## 4. 字面量里的 `*` / `**`：合并容器（PEP 448）

**这是 emit 里组装 record 用的那个语义。**

> [!success]- 造新容器
> ```python
> a = [1, 2]
> b = [3, 4]
> [*a, *b]              # [1, 2, 3, 4]
> [0, *a, 99]           # [0, 1, 2, 99]      ← 可以和普通元素混写
> (*a, *b)              # (1, 2, 3, 4)       ← tuple
> {*a, *b}              # {1, 2, 3, 4}       ← set（自动去重）
>
> d1 = {"x": 1, "y": 2}
> d2 = {"y": 99, "z": 3}
> {**d1, **d2}          # {'x': 1, 'y': 99, 'z': 3}   ← 后面的 y 赢了
> {"固定": 0, **d1}     # {'固定': 0, 'x': 1, 'y': 2} ← 和字面量键混写
> ```

### 覆盖规则：**后写的赢**

```python
{**d1, "y": 0}        # {'x': 1, 'y': 0}    ← 字面量在后，字面量赢
{"y": 0, **d1}        # {'x': 1, 'y': 2}    ← dict 在后，dict 赢
```

**这决定了一个设计问题**：把固定字段写在前面 = 允许调用方覆盖；写在后面 = 框架说了算。

### `{**d}` 是**浅拷贝**（重要，容易出 bug）

```python
original = {"conf": {"retry": 3}, "name": "job1"}
copy = {**original}

copy["name"] = "job2"
original["name"]              # 'job1'  ✅ 顶层互不影响

copy["conf"]["retry"] = 99
original["conf"]["retry"]     # 99      💥 里层是同一个对象！
copy["conf"] is original["conf"]   # True
```

`{**d}` 只复制了**最外面那一层**的键值对；值如果是可变对象（dict/list），两边指向的**还是同一个**。要彻底断开得 `copy.deepcopy`。

### 和 `update()` 的区别

```python
d1.update(d2)         # 就地修改 d1，返回 None——调用方手里的 d1 变了
new = {**d1, **d2}    # 造一个新的，d1 d2 都不动 ✅
```

写函数时优先用 `{**a, **b}`：**别人给你的数据是别人的，你只是路过。**

## 5. 光杆 `*` 和 `/`：强制传参方式

> [!info]- 裸星号：后面的只能用关键字传
> ```python
> def connect(host, *, timeout=30, retry=3):
>     ...
>
> connect("localhost", timeout=5)     # ✅
> connect("localhost", 5)             # ❌ TypeError: takes 1 positional argument but 2 were given
> ```
>
> **为什么要这样**：`connect("localhost", 5, 3)` 这种调用，读代码的人根本不知道 5 和 3 是什么。强制写成 `timeout=5` 之后，**调用处自带文档**。布尔参数尤其应该这么干（`send(msg, urgent=True)` vs `send(msg, True)`）。

> [!info]- 斜杠：前面的只能用位置传（3.8+）
> ```python
> def area(width, height, /, unit="m"):
>     ...
>
> area(3, 4)                  # ✅
> area(width=3, height=4)     # ❌ TypeError
> ```
>
> **为什么要这样**：形参名一旦能被调用方使用，就变成了**公开 API**——以后改名字就是破坏性变更。标准库大量使用（`len(obj, /)`），就是为了保留改名自由。

## 6. 透传模式：收集 + 展开的组合拳

**所有装饰器、包装函数的骨架**，也是 `*args`/`**kwargs` 最重要的实战用途。

> [!success]- 万能转发
> ```python
> def logged(fn):
>     def wrapper(*args, **kwargs):        # 收集：不管对方怎么调
>         print(f"调用 {fn.__name__}")
>         return fn(*args, **kwargs)       # 展开：原样转交
>     return wrapper
>
> @logged
> def book(hotel, nights=1):
>     return f"{hotel} {nights} 晚"
>
> book("如家", nights=3)      # 打印日志后返回 '如家 3 晚'
> ```
>
> **为什么必须用 `*args, **kwargs` 而不是写死形参**：写死之后，被包装的函数一旦新增参数，包装层就**默默挡住了**。`*args, **kwargs` 让包装层对签名变化免疫——**它不需要知道自己在转发什么。**

### 常见变体：改一改再转发

```python
def with_default_timeout(fn):
    def wrapper(*args, **kwargs):
        kwargs.setdefault("timeout", 30)     # kwargs 就是普通 dict，随便改
        return fn(*args, **kwargs)
    return wrapper
```

## 7. 其他会遇到的 `*`

### 赋值语句里的星号（extended unpacking）

```python
first, *rest = [1, 2, 3, 4]      # first=1, rest=[2, 3, 4]  ← 这里是 list！
*init, last = [1, 2, 3, 4]       # init=[1, 2, 3], last=4
a, *mid, z = "hello"             # a='h', mid=['e','l','l'], z='o'
```

⚠️ 注意：**赋值里的 `*` 收集成 list**，函数形参里的 `*` 收集成 tuple。同一个符号，容器类型不同。

### `print(*seq)` —— 最常用的展开

```python
names = ["张三", "李四"]
print(names)      # ['张三', '李四']       ← 打印列表本身
print(*names)     # 张三 李四              ← 展开成两个参数
print(*names, sep=" | ")   # 张三 | 李四
```

### `zip(*matrix)` —— 矩阵转置的经典写法

```python
matrix = [[1, 2, 3], [4, 5, 6]]
list(zip(*matrix))    # [(1, 4), (2, 5), (3, 6)]
# 因为 zip(*matrix) == zip([1,2,3], [4,5,6])
```

### 展开会**消耗**迭代器

```python
gen = (x for x in range(3))
print(*gen)       # 0 1 2
print(*gen)       # （什么都没有）← 生成器已经被榨干了
```

## 8. 陷阱速查

> [!danger]- 六个真会踩的
> 1. **`**` 展开的键必须对上形参名**——它是"填坑"，不是"传数据"。（你的 `open(**payload)`）
> 2. **形参撞车报错，非形参撞车静默**：
>    ```python
>    def log(level, **f): return {"level": level, "seq": 1, **f}
>    log("INFO", level="X")   # ❌ TypeError（level 是形参，响的失败）
>    log("INFO", seq=999)     # 😱 {'level':'INFO','seq':999}（seq 不是形参，静默覆盖）
>    ```
> 3. **`{**d}` 是浅拷贝**，内层可变对象仍然共享。
> 4. **展开消耗生成器**，第二次展开是空的。
> 5. **`*args` 是 tuple，不能 append**；赋值语句里的 `*rest` 才是 list。
> 6. **`**` 展开只要求键是「字符串」，不要求是「合法标识符」**（很多人记反）：
>    ```python
>    def g(**kw): return kw
>    g(**{"a-b": 1})    # ✅ {'a-b': 1}  —— 不是合法变量名，照样能进 kwargs
>    g(**{1: 2})        # ❌ TypeError: keywords must be strings
>    ```
>    但 `a-b` 这种键**永远只能待在 `**kwargs` 里**——形参名必须是合法标识符，所以它不可能对上任何具名形参。而**直接手写** `g(a-b=1)` 是 SyntaxError（那是在写代码，不是在展开数据）。

## 9. 一页速查表

| 写法 | 位置 | 含义 | 结果类型 |
|---|---|---|---|
| `def f(*args)` | 形参表 | 收集多余位置参数 | tuple |
| `def f(**kw)` | 形参表 | 收集多余关键字参数 | dict |
| `def f(a, *, b)` | 形参表 | `b` 只能关键字传 | — |
| `def f(a, /, b)` | 形参表 | `a` 只能位置传 | — |
| `f(*seq)` | 调用括号 | 拆成多个位置实参 | — |
| `f(**d)` | 调用括号 | 拆成多个关键字实参（键=形参名） | — |
| `[*a, *b]` | 字面量 | 合并 | list |
| `(*a, *b)` | 字面量 | 合并 | tuple |
| `{*a, *b}` | 字面量 | 合并去重 | set |
| `{**a, **b}` | 字面量 | 合并，后者覆盖前者 | dict（浅拷贝） |
| `a, *rest = seq` | 赋值 | 收集剩余元素 | **list** |

**三问自查**（写 `*`/`**` 之前过一遍）：

1. 我在**造函数**还是**调函数**还是**造容器**？→ 决定是收集、展开还是合并
2. 如果是展开：这个 dict 的键，是**对方形参的名字**吗？
3. 如果是合并：谁写在后面？**后面的会覆盖前面的。**
