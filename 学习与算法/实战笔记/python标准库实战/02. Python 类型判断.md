# Python 类型判断：`isinstance` / 鸭子类型 / 问磁盘的区别

写通用函数（处理"任意值"的那种）绕不开一件事：**先搞清楚手里这个东西是什么，再决定怎么处理它**。Python 是动态类型，变量上没有牌子，只能在运行时问。

但"问类型"这件事本身有**三种完全不同的问法**，混起来就会写出"文件存在时正常、不存在时静默走错分支"这类找不到原因的 bug。这一篇先把三种问法分开，再讲每种怎么写。

---

## 思路

同一个变量 `value`，下面三个问题听起来像一个，其实毫无关系：

| 问题 | 在问什么 | 用什么答 | 会变吗 |
| --- | --- | --- | --- |
| **身份**：它是什么类型？ | 内存里这个对象属于哪个类 | `isinstance(value, X)` | 不会，对象造出来就定了 |
| **能力**：它能做什么？ | 有没有某个方法／属性 | `hasattr` / 直接 try | 不会 |
| **事实**：它指向的东西怎么样？ | 磁盘、网络、数据库的**外部状态** | `.is_file()` / `.exists()` | **会！随时可能变** |

> [!tip]- 核心思路
> **前两个问题问的是"这个对象"，第三个问题问的是"外面的世界"。**
>
> 判断依据：这个调用会不会**因为换一台机器、换一个时刻而给出不同答案**？会 → 你问的是事实，不是类型。纯粹的数据处理函数**不该问事实**。

---

## 1. `isinstance` 与 `type`：问身份

```python
isinstance(value, str)              # 最常用：是不是字符串（含子类）
isinstance(value, (list, tuple))    # 传元组 = 任意一个命中即可
isinstance(value, int | str)        # Python 3.10+ 的等价写法
type(value) is str                  # 精确相等，不认子类
type(value).__name__                # 'str' —— 拿类型名，写错误信息用
```

> [!success]- 该用哪个
> **默认用 `isinstance`**，因为它认子类——子类应该能用在父类能用的地方（里氏替换）。只有在你**明确要排除子类**时才用 `type(x) is X`。
>
> 最典型的场景就是 `bool`：
> ```python
> isinstance(True, int)     # True  ← bool 是 int 的子类！
> type(True) is int         # False
> ```
> 想接受整数但**拒绝布尔**（`True` 混进数值运算是经典静默 bug，见 [worked-examples.md §1](worked-examples.md)），就得显式挡：
> ```python
> if isinstance(x, bool) or not isinstance(x, int):
>     raise TypeError(...)
> ```

### 常见类型速查

| 想判断 | 写法 | 备注 |
| --- | --- | --- |
| 字符串 | `isinstance(v, str)` | `bytes` 不是 `str` |
| 整数（排除 bool） | `isinstance(v, int) and not isinstance(v, bool)` | |
| 数值 | `isinstance(v, (int, float))` | 需要 `Decimal`/复数时用 `numbers.Number` |
| 列表或元组 | `isinstance(v, (list, tuple))` | |
| 字典 | `isinstance(v, dict)` | 想接受任何"映射"用 `Mapping`，见 §4 |
| **是不是 None** | `v is None` | **不要**写 `isinstance(v, type(None))` |
| 能不能调用 | `callable(v)` | 函数、类、带 `__call__` 的对象都算 |
| 路径对象 | `isinstance(v, Path)` | 想同时接受 `str` 和 `Path` 用 `os.PathLike`，见 §5 |

## 2. 分支顺序陷阱：**子类和"长得像容器的东西"必须排前面**

按类型分派时，分支顺序**不是随便排的**。两个必考的坑：

> [!warning]- 坑一：`bool` 必须排在 `int` 前面
> ```python
> if isinstance(v, int):     # True 会在这里被拦下
>     ...
> elif isinstance(v, bool):  # 永远执行不到 —— 死代码
>     ...
> ```

> [!warning]- 坑二：**字符串也是"可迭代对象"**——递归函数的头号杀手
> ```python
> from collections.abc import Iterable
> isinstance("abc", Iterable)   # True  😱
> isinstance("abc", Sequence)   # True  😱
> ```
>
> 于是这样的递归会**无限递归**：
> ```python
> def walk(v):
>     if isinstance(v, Iterable):     # ❌ 字符串中招
>         return [walk(x) for x in v]
>     return v
>
> walk("ab")   # RecursionError: maximum recursion depth exceeded
> ```
>
> 原因很有意思：**`"a"[0]` 还是 `"a"`**——单字符字符串迭代出来还是单字符字符串，长度永远是 1，**永远拆不到底**，没有递归终点。
>
> **两个解法**：① 把 `str` 的分支**排在容器分支之前**（先被拦下就不会往下走）；② 别用 `Iterable`，老老实实写 `isinstance(v, (list, tuple))`——**明确列出你要的容器类型**，而不是用一个连字符串都包括的大类。

**通用规律**：**范围越窄的分支越靠前。** 一旦某个值能同时满足两个分支，先写的那个赢。

## 3. 鸭子类型：问能力，不问身份

"如果它走起来像鸭子、叫起来像鸭子，那就当它是鸭子。"——不关心它是什么类，只关心它**能不能干这件事**。

```python
hasattr(value, "read")      # 能不能当文件对象读
hasattr(value, "name")      # 有没有 name 属性
```

> [!tip]- LBYL vs EAFP：先看再跳，还是先跳再说
> ```python
> # LBYL (Look Before You Leap)：先检查
> if hasattr(value, "read"):
>     data = value.read()
>
> # EAFP (Easier to Ask Forgiveness than Permission)：先做，错了再说
> try:
>     data = value.read()
> except AttributeError:
>     data = str(value)
> ```
> **Python 社区偏爱 EAFP**，因为检查和使用之间对象可能变、而且检查本身也可能漏。
>
> 但**处理"任意类型的数据"时反而该用 `isinstance`**：这时候类型就是你的业务逻辑（不同类型要走不同处理），不是"顺便试试能不能"。**用 `try/except AttributeError` 兜类型分派会把真正的 bug 也吞掉**——比如你的处理函数内部拼错了属性名，也会被当成"类型不对"静默跳过。

## 4. 抽象基类：想接受"任何字典类"的东西

```python
from collections.abc import Mapping, Sequence, Iterable

isinstance({}, Mapping)          # True —— dict、OrderedDict、defaultdict 都算
isinstance([], Sequence)         # True
isinstance("abc", Sequence)      # True  ← 又是这个坑
```

**什么时候值得用**：写库、要接受用户传进来的任意 dict-like（比如 `OrderedDict`、`ChainMap`）。**什么时候不用**：自己项目内部数据结构可控，`isinstance(v, dict)` 更直白，也不会误伤字符串。

## 5. 回到你的问题：**"是不是 file" 有三种问法**

这是本篇的重点。同一句中文对应三个不同的代码，选错就是 bug。

```python
from pathlib import Path
s = "/home/leyan/不存在.txt"
p = Path(s)
```

| 你真正想问的 | 写法 | 实测结果 | 特点 |
| --- | --- | --- | --- |
| 这变量是不是 `Path` **类型** | `isinstance(p, Path)` | `True` | 纯内存，永远不变 |
| 磁盘上**真的存在**这个文件吗 | `p.is_file()` | **`False`** | **读磁盘**，换机器就变 |
| 这字符串**长得像**绝对路径吗 | `s.startswith("/")` | `True` | 纯字符串形状 |
| 同上，跨平台版 | `p.is_absolute()` | `True` | 不碰磁盘，认 Windows 盘符 |

> [!warning]- `is_file()` 为什么在数据处理函数里几乎总是错的
> 它问的是**外部世界此刻的状态**，带来三个后果：
> 1. **不纯**：同样的输入，在你机器上和同事机器上结果不同；文件被删了结果又不同。函数不再可预测，测试也难写（得先造文件）。
> 2. **慢**：每次调用都是一次系统调用（syscall）。循环里跑几万次就很可观。
> 3. **TOCTOU 竞态**：检查（Time Of Check）和使用（Time Of Use）之间文件可能被删掉/换掉，检查结论已经过期。
>
> **判据**：你的函数是在**处理数据**，还是在**操作文件**？处理数据（清洗、转换、格式化）→ 只问身份和形状；真要读写文件 → 才问事实，而且此时更该用 EAFP：直接 `open()` 然后 `except FileNotFoundError`，而不是先 `is_file()` 再 `open()`（那之间正好是竞态窗口）。

> [!tip]- `Path` 和 `str` 的关系（容易搞混）
> ```python
> isinstance(Path("/a"), str)           # False  ← Path 不是 str！
> isinstance(Path("/a"), os.PathLike)   # True   ← 这才是它的"路径身份"
> hasattr("abc", "name")                # False  ← 字符串没有 .name
> ```
> 所以：**专门写给 `str` 的分支接不住 `Path`**，反过来 `Path` 的方法（`.name` / `.is_file()` / `.suffix`）在 `str` 上全是 `AttributeError`。
>
> 想让函数同时吃 `str` 和 `Path`，标准做法是**在入口统一成一种**（`value = str(value)` 或 `value = Path(value)`），后面就只有一种类型要操心。想在类型注解里表达"两者都行"用 `os.PathLike | str`。

## 6. 类型注解**不是**运行时检查

```python
def f(x: int) -> int:
    return x

f("我是字符串")      # '我是字符串' —— 照跑不误，一点错都不报
```

注解是**给人和工具看的文档**（IDE 补全、mypy 静态检查），解释器**完全不管**。想在运行时挡住错误类型，必须自己写 `isinstance` + `raise`。

---

## 7. 常见易错点

> [!warning]- 易错点
> - **拿"有没有某属性"当类型判断**：`if value.name:` —— 非 `Path` 直接 `AttributeError`，而且 `Path("/").name` 是**空串**（假值），会静默落到分支外面。
> - **拿"能不能读磁盘"当类型判断**：`is_file()` 对不存在的文件返回 `False`，你的保护逻辑就此失效——**静默**。
> - **分支漏了兜底 `return`**：Python 会替你返回 `None`，值被悄悄吃掉。递归函数尤其致命（少了终点直接 `RecursionError`）。
> - **`bool` 排在 `int` 后面** → 死代码。
> - **用 `Iterable` / `Sequence` 判容器** → 字符串中招，递归函数无限递归。
> - **`isinstance(v, type(None))`** → 直接写 `v is None`。
> - **以为类型注解会拦住参数** → 不会，一个都拦不住。
> - **`try/except AttributeError` 当类型分派** → 会把函数内部真正的拼写错误一起吞掉。

## 复杂度

> [!summary]- 复杂度
> - `isinstance` / `type`：$O(1)$（继承链很短，可视为常数），纯内存。
> - `hasattr`：$O(1)$，但它实际上是**执行一次属性查找并吞掉异常**，property 会真被调用，可能有副作用。
> - `is_file()` / `exists()`：**一次系统调用**，比前两者慢几个数量级，且结果可变。

---

## 一句话总结

判断类型前先分清你在问哪一种问题：**身份**用 `isinstance`（默认认子类，`bool` 是 `int` 子类要单挡）、**能力**用鸭子类型（但类型即业务逻辑时仍该用 `isinstance`）、**事实**（磁盘上存不存在）只在真要操作文件时才问——数据处理函数里问磁盘，就是把"环境状态"偷偷混进了"数据逻辑"。

## 模板归纳

```python
# 处理任意值的通用函数：按类型分派，窄的排前面，最后必有兜底
def handle(value):
    if isinstance(value, Path):          # 先归一：Path 转成 str 再走下面的规则
        value = str(value)
    if isinstance(value, str):           # str 必须排在容器之前，否则被当容器拆
        return handle_text(value)
    if isinstance(value, dict):
        return {k: handle(v) for k, v in value.items()}
    if isinstance(value, (list, tuple)):  # 明确列类型，别用 Iterable
        return [handle(x) for x in value]
    return value                          # ← 兜底：递归终点，绝不能少

# 运行时挡住错误类型（注解做不到）
if not isinstance(n, int) or isinstance(n, bool):
    raise TypeError(f"需要整数，收到 {type(n).__name__}: {n!r}")

# 真要读文件：EAFP，别先 is_file() 再 open()（中间有竞态窗口）
try:
    text = path.read_text(encoding="utf-8")
except FileNotFoundError:
    text = ""
```
