# Python json.loads / json.dumps：字符串 ↔ Python 对象的解析与序列化

`json.loads(s)` 把 **JSON 字符串**解析成 Python 对象（dict/list/…），`json.dumps(obj)` 反过来把对象序列化成字符串。凡是**从外部拿到的是一段文本、但你要按结构操作它**（API 响应、LLM tool call 的 arguments、配置、日志行）时就需要它——关键认知是：**拿到的 `arguments` 是字符串，不 `loads` 就没法当 dict 用。**

来源：task_011 `_parse_response` 解析 tool call 的 `.function.arguments`（2026-07-21）。踩坑：把没解码的原始字符串直接传给 `intent_from_tool_call`，被 `isinstance(x, dict)` 挡成 `unknowns=None`。

---

## 思路

真实 SDK / FakeLLM 给的 `tool_calls[0].function.arguments` 是**一段字符串**，比如 `'{"unknowns": 1000000}'`——注意最外层的引号，它整体是 `str`，不是 dict。你想读里面的 `unknowns`，必须先 `json.loads` 变成真正的 dict 才能 `d["unknowns"]` 或 `d.get(...)`。

不 `loads` 直接用会有两种典型错误：
1. 把字符串当 dict 传给下游，`isinstance(s, dict)` 为 False，被兜底逻辑默默丢弃（我踩的就是这个）。
2. 对字符串下标 `s["unknowns"]`，Python 会当成"字符串切片索引"抛 `TypeError: string indices must be integers`。

而模型/外部给的字符串**不保证是合法 JSON**（可能是 `'not-json{'`），所以 `loads` 必须用 `try/except` 包住——这就是"防御式解析"。

> [!tip]- 核心思路
> 字符串进来先解码，解码要包异常：
>
> ```python
> import json
> try:
>     obj = json.loads(raw)          # str -> dict/list/...
> except json.JSONDecodeError:
>     return {"intent": "unknown", "unknowns": None}  # 坏 JSON 的兜底
> # 到这里 obj 才是能下标/.get() 的 dict
> ```
>
> 不变量：`loads` 之后才是 dict，之前永远是 str；`JSONDecodeError` 是 `ValueError` 的子类。

## 1. 导入与创建

标准库自带，`import json` 即可，无需 `pip install`。

> [!success]- 基础语法
> ```python
> import json
>
> # 字符串 -> 对象
> obj = json.loads('{"a": 1, "b": [2, 3]}')   # {'a': 1, 'b': [2, 3]}
>
> # 对象 -> 字符串
> s = json.dumps({"a": 1})                      # '{"a": 1}'
>
> # loads 读字符串；load(无 s)读文件对象
> # with open("x.json") as f: obj = json.load(f)
> ```

## 2. 核心操作

| 操作 | 作用 | 注意事项 |
| --- | --- | --- |
| `json.loads(s)` | JSON **字符串** → Python 对象 | `s` 必须是 `str`/`bytes`；坏格式抛 `JSONDecodeError` |
| `json.dumps(obj)` | Python 对象 → JSON **字符串** | 中文默认转义成 `\uXXXX`，见第 3 节 |
| `json.load(fp)` | 从**文件对象**读并解析 | 参数是打开的文件，不是路径字符串 |
| `json.dump(obj, fp)` | 序列化并写入文件对象 | —— |

> [!example]- 最小示例
> ```python
> import json
>
> raw = '{"unknowns": 1000000}'      # 注意：整体是一个字符串
> print(type(raw))                   # <class 'str'>
>
> data = json.loads(raw)
> print(type(data))                  # <class 'dict'>
> print(data["unknowns"])            # 1000000  <- 解码后才能下标
> ```

---

## 3. 关键行为与边界

> [!tip]- JSON 类型 → Python 类型的对应
> `object→dict`、`array→list`、`string→str`、`number(int)→int`、`number(real)→float`、`true/false→True/False`、`null→None`。
> 所以 JSON 里的 `true` 解出来是 Python 的 `True`（bool），这正是 `intent_from_tool_call` 要先挡 bool 的原因。

> [!warning]- 边界条件
> - **坏 JSON 抛 `json.JSONDecodeError`**：如 `json.loads("not-json{")`。它是 `ValueError` 的子类，所以 `except ValueError` 也能抓到，但**精确写 `except json.JSONDecodeError` 更表意**，别用裸 `except:`。
> - **空字符串 `json.loads("")` 也抛 `JSONDecodeError`**（不是返回 None）。
> - **单引号不是合法 JSON**：`json.loads("{'a': 1}")` 会抛错——JSON 规定字符串用双引号。这也是为什么不能用 `eval` 代替（`eval` 还有安全问题）。
> - **`loads` 需要的是字符串**：把已经是 dict 的东西再 `loads` 会抛 `TypeError`。搞不清手上是 str 还是 dict 时，先 `print(type(x))`。

## 4. 实例一：解析 LLM tool call 的 arguments（本任务原型）

输入是响应对象里的 `arguments` 字符串，目标是安全地拿到里面的参数 dict；因为字符串可能非法，必须 `try/except`。

> [!success]- 完整实现
> ```python
> import json
>
> def decode_arguments(raw: str):
>     """把 tool call 的 arguments 字符串解成 dict，坏 JSON 返回 None。"""
>     try:
>         return json.loads(raw)          # str -> dict
>     except json.JSONDecodeError:
>         return None                     # 防御：模型给了非法 JSON
>
>
> print(decode_arguments('{"unknowns": 1000000}'))  # {'unknowns': 1000000}
> print(decode_arguments('not-json{'))              # None
> print(decode_arguments('{}'))                     # {}  <- 合法空对象，非 None
> ```
> 关键：**解码后的返回值才能往下游传**（`intent_from_tool_call` 要 dict，传原始字符串会被 `isinstance` 挡掉）。最容易写错的位置——decode 出来存进一个变量后，下一行别又把原始字符串传出去。

## 5. 实例二：算法/工程里逐行解析 JSON 日志（NDJSON）

很多日志是"每行一个 JSON 对象"（NDJSON / JSON Lines）。逐行 `loads`，坏行跳过并计数——体现 `loads` + 异常处理的典型组合。

> [!success]- 完整实现
> ```python
> import json
>
> def parse_ndjson(lines):
>     """逐行解析 JSON，返回 (成功对象列表, 坏行数)。"""
>     objs, bad = [], 0
>     for line in lines:
>         line = line.strip()
>         if not line:                    # 跳过空行
>             continue
>         try:
>             objs.append(json.loads(line))
>         except json.JSONDecodeError:
>             bad += 1                     # 坏行不让整个流程崩
>     return objs, bad
>
>
> data, bad = parse_ndjson(['{"id": 1}', 'oops', '', '{"id": 2}'])
> print(data)   # [{'id': 1}, {'id': 2}]
> print(bad)    # 1
> ```
> [!summary]- 当前实例复杂度
> - 时间复杂度：$O(N \cdot L)$，N 行、每行长度 L（`loads` 与行长成正比）。
> - 空间复杂度：$O(N \cdot L)$，存下所有成功对象；坏行不占额外结构。

## 6. 与相近写法怎么选

| 需求 | 推荐写法 | 原因 |
| --- | --- | --- |
| 手上是**字符串** | `json.loads(s)` | `load`（无 s）要文件对象，传字符串会报错 |
| 手上是**文件** | `json.load(open_file)` | 省一次 `.read()`；直接吃文件对象 |
| 解析不可信输入 | `json.loads` + `try/except` | 永不用 `eval`：`eval` 能执行任意代码、且不认 JSON 的 `true/null` |
| 输出给人看的中文 JSON | `json.dumps(obj, ensure_ascii=False)` | 默认 `ensure_ascii=True` 会把中文转成 `\uXXXX` |

只保留会影响选择的差异：`loads` vs `load` 的区别只在"字符串还是文件"，别记混。

---

## 7. 常见易错点

> [!warning]- 易错点
> - **解码后不用解码结果**：`args = json.loads(raw)` 之后却把 `raw`（原字符串）传给下游 → 被当非 dict 丢弃。**转完就用转完的那个变量。**（本任务真实踩坑）
> - **`except` 分支不 return，直接漏到后面**：坏 JSON 时只 `append`/`pass` 没 `return`，控制流掉到正常路径又用坏数据算一遍。异常分支要**明确 return 兜底值**。
> - **把 dict 再 `loads`**：`json.loads({"a":1})` → `TypeError`。分不清就 `print(type(x))`。
> - **裸 `except:` 吞掉一切**：会连 `KeyboardInterrupt` 都吃掉，且掩盖真 bug。精确写 `except json.JSONDecodeError`。
> - **中文被转义**：`json.dumps("你好")` → `'"\\u4f60\\u597d"'`；要可读加 `ensure_ascii=False`。

## 复杂度

> [!summary]- 复杂度
> - 核心操作：`json.loads(s)` 时间 $O(L)$，L 为字符串长度（需扫一遍并建对象）。
> - 完整流程（逐行解析 N 行）：$O(N \cdot L)$。
> - 额外空间：$O(L)$（解析出的对象规模），来自新建的 dict/list 结构本身。

---

## 一句话总结

**外部给的是字符串就先 `json.loads` 变对象、且必须 `try/except json.JSONDecodeError` 兜底**——这是"字符串 → 结构化数据"的标准入口，解码后务必用解码结果本身，别再碰原始字符串。

## 模板归纳

看到以下信号时，优先想到 `json.loads`：
- 拿到的是**一段文本**（API/LLM 响应、`arguments`、日志行、配置），但你想按 key/index 读它
- 出现 `TypeError: string indices must be integers`（下标了没解码的字符串）
- 下游要 dict，你却传进去被 `isinstance(x, dict)` 挡掉
- 需要"坏输入不崩、给个兜底值"的防御式解析

```python
# 可直接复用的最小模板：字符串 -> 对象，坏格式兜底
import json

def safe_loads(raw, default=None):
    try:
        return json.loads(raw)
    except json.JSONDecodeError:
        return default
```
