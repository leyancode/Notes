```python
class Solution:
    def permute(self, nums: List[int]) -> List[List[int]]:
        n = len(nums)
        ans = []
        path = [0] * n
        def dfs(i, s):
            if i == n:
                ans.append(path.copy())
                return
            for x in s:
                path[i] = x
                dfs(i+1, s-{x})
        dfs(0,set(nums))
        return ans
```
### 整体框架

排列问题的本质是：**有 n 个坑位，依次决定每个坑填谁**。

```
dfs(i, s) 的含义：
  前 i 个坑已经填好了
  s 是还没被用过的数字
  任务：把第 i 个坑到最后一个坑填完
```

所以 `i` 是"填到哪儿了"，`s` 是"还剩什么可用"。递归到 `i == n` 说明坑填满了，收下一个答案。
### set 在这里干什么

`s` 就是**候选池**。排列的约束是"每个数只能用一次"，用集合表示"还没用过的数"最自然：

python

```python
for x in s:          # 枚举第 i 个坑的所有可能填法
    path[i] = x
    dfs(i+1, s-{x})  # 这个数用掉了，从候选池里去掉
```

关键在 `s - {x}` 这个**集合差集**运算。它不修改 `s`，而是**新建一个集合**返回：

python

```python
s = {1, 2, 3}
t = s - {2}   # t 是新集合 {1, 3}
print(s)      # s 仍然是 {1, 2, 3}，没变
```

对比会修改原集合的写法：

python

```python
s.remove(2)   # 就地修改，s 变成 {1, 3}，原来的没了
```

这就是这段代码不需要"恢复现场"的原因——**每一层拿到的是自己的一份副本，从来没动过上一层的东西**。上一层的 `s` 完好无损，for 循环下一轮自然还是完整的候选池。

> 类比：不用 `remove/add` 的"借了要还"，而是每次**复印一份名单，在复印件上划掉一个名字**再交给下一层。原件永远干净。

### 那 path 为什么也不用恢复？

`path` 是真正共享的可变对象，从头到尾只有一个。它没有 pop，却依然正确——原因和上面不同：

**第 i 层只写 `path[i]` 这一格，而且一定先写后递归。**

所以当 `i == n` 时，`path[0..n-1]` 全都被本条路径上的第 0 层到第 n-1 层刚刚写过了。上一条路径留下的旧值不可能残留——**任何一格在被读到之前，必然已经被当前路径覆盖**。这就是这个写法的不变量。

而 append/pop 版本的 `path` 长度是变化的，pop 才能让长度回到正确状态；这里长度恒为 `n`，靠"下标定位 + 无条件覆盖"就够了。两种写法的不变量不同，但目的一样：**保证每层看到的状态是干净的**。

### 一个小推演

`nums = [1, 2, 3]`：

```
dfs(0, {1,2,3})
 └ x=1: path=[1,_,_]  dfs(1, {2,3})
    ├ x=2: path=[1,2,_]  dfs(2, {3})
    │   └ x=3: path=[1,2,3]  dfs(3,{}) -> 收 [1,2,3]
    └ x=3: path=[1,3,_]  dfs(2, {2})
        └ x=2: path=[1,3,2]  -> 收 [1,3,2]
```

注意回到 `dfs(1,·)` 的第二轮时，它手上的 `s` 依然是 `{2,3}`——因为从没被改过。

### set() 是什么

`set` 是 Python 的**集合**类型，两个核心特性：**元素不重复**、**查找是 O(1)O(1) O(1)**。

python

```python
s = set()          # 空集合（注意：{} 是空字典，不是空集合）
s.add(3)           # 加入元素
s.add(3)           # 重复加入，集合不变
3 in s             # True，O(1) 判断存在性
s.remove(3)        # 删除（元素不存在会报错）
s.discard(3)       # 删除（元素不存在也不报错）
len(s)             # 元素个数

set([1, 2, 2, 3])  # 从 list 建集合 => {1, 2, 3}，顺便去重
```

### 为什么快：底层是 Hash

`set` 和 `dict` 底层都是哈希表。判断 `x in s` 时，不是逐个遍历比较，而是对 `x` 算一次 hash 直接定位。对比：

python

```python
x in my_list   # O(n)，逐个扫
x in my_set    # O(1)，hash 定位
```

这就是为什么算法题里"记录见过的元素"几乎总用 `set` 而不用 `list`。

### 在你熟悉的题里的位置

- **环形链表**（哈希解法）：用 `visited = set()` 记录走过的节点，再次遇到说明有环——对应你笔记里快慢指针的替代方案，代价是 O(n)O(n) O(n) 空间。
- **滑动窗口**：维护"窗口内是否存在某元素"，比如无重复字符最长子串。
- **去重**：`set(nums)` 一步去重，但注意会**丢失顺序**。

一个常见坑：`set` 里只能放**可哈希（不可变）**的东西——数字、字符串、tuple 可以，`list` 不行：

python

```python
s.add([1, 2])        # TypeError: unhashable type
s.add((1, 2))        # OK，用 tuple 代替
```

也可以考虑使用布尔数组：

```python
class Solution:
    def permute(self, nums: List[int]) -> List[List[int]]:
        n = len(nums)
        ans = []
        path = [0] * n
        on_path = [False] * n
        def dfs(i):
            if i == n:
                ans.append(path.copy())
                return
            for j in range(n):
                if not on_path[j]:
                    path[i] = nums[j]
                    on_path[j] = True
                    dfs(i+1)
                    on_path[j] = False
        dfs(0)
        return ans
```
这是全排列的**经典写法**，也是面试里更常见的一版。它和 set 版是同一棵递归树，只是"记录谁被用过"的方式换了。
### 两版的对应关系

```
set 版：  s          = 还没用的数字（值的集合）
布尔版：  on_path[j] = 下标 j 的数字是否已被用
```

for 循环的方向也随之翻转：

python

```python
for x in s:                   # set 版：直接遍历候选池
for j in range(n):            # 布尔版：遍历所有下标，用 if 过滤掉不可用的
    if not on_path[j]:
```

set 版是"池子里只剩合法的"，布尔版是"全都看一遍，跳过非法的"。结果等价，但布尔版**没有新建集合的开销**——这是它的主要优势。

### 关键：为什么 on_path 必须恢复，path 却不用

这是这段代码最值得琢磨的一点，两个数组待遇完全不同：

python

```python
path[i] = nums[j]
on_path[j] = True
dfs(i+1)
on_path[j] = False    # 只还这一个
```

区别在于**下标的含义**：

||下标是什么|会不会撞车|
|---|---|---|
|`path[i]`|`i` = 递归深度|不会。每层独占一格|
|`on_path[j]`|`j` = 数字在 nums 中的位置|会。所有层共用同一张表|

`path[i]` 的 `i` 就是当前层号，第 3 层永远只碰 `path[3]`，兄弟分支之间不会互相污染，而且下次进来一定会先覆盖再用——所以不需要还。

`on_path` 则是**整棵树共享的一张占用表**。第 1 层把 `on_path[0]` 设成 True，是在告诉底下所有子孙"0 号被我占了"。子树探索完毕，这个占用必须撤销，否则 for 循环的下一轮兄弟分支会误以为 0 号仍被占用——它就永远用不到那个数字了。

> 你之前总结过的"借了要还"在这里依然成立，只是**还的对象是 `on_path`，不是 `path`**。判断标准不是"哪个变量是共享的"，而是"哪个变量的状态会被兄弟分支读到"。

### 易错点

**1. 忘记 `on_path[j] = False`**

最高频错误。后果不是崩溃，而是**答案严重变少**——每个数字全局只会被用一次，最后只能得到 1 个排列（甚至 0 个）。

**2. 恢复写在 `if` 外面**

python

```python
for j in range(n):
    if not on_path[j]:
        ...
        dfs(i+1)
    on_path[j] = False    # 错：把别人占的位也给清了
```

必须严格包在 if 内部，跟 `= True` 配对。**谁占的谁还**。

**3. `path[i] = j` 写成下标而不是值**

要填的是 `nums[j]`。`on_path` 记的是下标，`path` 存的是值，两者别混。

**4. `ans.append(path)` 忘记 copy**

老朋友了，同 set 版。

**5. 循环变量写成 `for j in range(i, n)`**

排列不是组合，每层都要从 0 开始扫全部下标——后面的数可以排在前面。写成 `range(i, n)` 就变成子集/组合了。

### 复杂度对比

||时间|空间（不含答案）|
|---|---|---|
|set 版|O(n2⋅n!)O(n^2 \cdot n!) O(n2⋅n!)|O(n2)O(n^2) O(n2)|
|布尔版|O(n⋅n!)O(n \cdot n!) O(n⋅n!)|O(n)O(n) O(n)|

布尔版每层是 O(n)O(n) O(n) 的扫描但**不复制任何东西**，栈上只有 nn n 个整数帧；set 版每层要新建一个 O(n)O(n) O(n) 集合，深度 nn n 层就挂了 O(n2)O(n^2) O(n2) 的集合。

面试建议：**写布尔版，提一句 set 版更直观**。

排列 = 逐位填坑 + 一张全局占用表；`path` 靠"深度定位、无条件覆盖"自动保持干净，`on_path` 靠"谁占谁还"手动维持不变量。
