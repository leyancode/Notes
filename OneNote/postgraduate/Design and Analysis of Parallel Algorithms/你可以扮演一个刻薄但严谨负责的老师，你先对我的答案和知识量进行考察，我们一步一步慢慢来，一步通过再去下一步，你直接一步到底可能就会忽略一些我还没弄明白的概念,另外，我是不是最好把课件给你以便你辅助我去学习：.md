**7.2** **算法直觉（先讲人话，再写伪代码）**  
矩阵乘：C = A×B  
每个 C(i,j) 需要把 A(i,k) 和 B(k,j) 的贡献累加所有 k。  
做法（SUMMA 思想）：

- 总共 q 轮（k=0..q-1）
- 第 k 轮：
    - ==每个进程需要得到本轮的== ==A(i,k)====（同一行共享）和== ==B(k,j)====（同一列共享）==
    - 所以：
        - 在每一行做一次 broadcast：把 A(i,k) 广播给该行所有进程
        - 在每一列做一次 broadcast：把 B(k,j) 广播给该列所有进程
    - 然后本地做一次块乘并累加到 C(i,j)

这正好把通信限制在“行与列”，非常贴合 2D mesh。  
￼￼  
parallel for each process P(i,j) do  
for k = 0 .. q-1 do  
RowBroadcast A(i,k)  
ColBroadcast B(k,j)  
C(i,j) += A(i,k) * B(k,j)  
endfor  
end parallel  
￼￼￼==Algorithm: Distributed Matrix Multiply on 2D Mesh (SUMMA-style)==  
==Input: local blocks Ablk, Bblk on each P(i,j)==  
==Output: local block Cblk on each P(i,j)==
 
==q = sqrt(p)==  
==b = n / q==  
==Cblk = zeros(b,b)==
 
==for k = 0 .. q-1 do==  
==// 1) broadcast A(i,k) along row i==  
==if j == k then==  
==Abuf = Ablk // this process owns A(i,k)==  
==end==  
==Abuf = RowBroadcast(i, root_col = k, data = Abuf)==
 
==// 2) broadcast B(k,j) along column j==  
==if i == k then==  
==Bbuf = Bblk // this process owns B(k,j)==  
==end==  
==Bbuf = ColBroadcast(j, root_row = k, data = Bbuf)==
 
==// 3) local compute==  
==Cblk = Cblk + Abuf * Bbuf==  
==endfor==
 
==return Cblk==￼￼  
**7.4** **时间复杂度：一行写清** **Tcomp****，一行写清** **Tcomm**  
**7.4.1** **本地计算时间** **Tcomp**  
每轮本地做一次 b×b 块乘：

- 代价 Θ(b³)￼总共 q 轮：
- Tcomp = Θ(q · b³)

代入 b = n/q：

- Tcomp = Θ(q · (n/q)³) = Θ(n³ / q²) = Θ(n³ / p)

这就是你最希望出现的“理想计算项”。  
**7.4.2** **通信时间** **Tcomm****（按****“****次数** **×** **代价****”****写）**  
每一轮有两次广播：

- 一次行广播（长度 q）
- 一次列广播（长度 q）￼消息大小：一个块，s = b² 个元素

在 store-and-forward + mesh 上，一个“沿行传播的广播”你可以用下面这种稳健写法：

- RowBroadcast cost = Θ(q (α + β s))￼同理列广播也是：
- ColBroadcast cost = Θ(q (α + β s))

每轮两次：

- Tcomm_per_round = Θ(q (α + β s))

总共 q 轮：

- Tcomm = Θ(q² (α + β s))

代入 q=√p，s=b²=(n/q)² = n²/p：

- Tcomm = Θ(p α + p β (n²/p))
- Tcomm = Θ(p α + β n²)

解释一句就能拿分：

- 延迟项（α）会随轮数与传播跳数累积，p 大时可能变成瓶颈
- 带宽项在这个分解下常见会变成 Θ(n²) 级别（因为块变小了）

最后总时间：

- Tp = Θ(n³/p + pα + βn²)

考试里如果你不想展开到这么细，也可以保守写成：

- Tp = Θ(n³/p + √p·q? 形式)￼但上面这个写法更“像课上 Lec6/7 的风格”，得分更稳。

**7.5 cost-optimal** **讨论（按套路写就能得分）**  
串行时间：

- T1 = Θ(n³)

并行 cost：

- Cost = p · Tp
- = Θ(n³ + p²α + pβn²)

要 cost-optimal，需要 Cost = Θ(n³)。  
显然当 p 增大时，p²α 和 pβn² 会把 cost 拉大，所以：  
结论写法（得分版）：

- 该算法在 p 不是太大时接近 cost-optimal（计算项主导）
- 当 p 增大到使通信项主导时不再 cost-optimal
- 因此存在一个“最佳 p 区间”，由 n 与网络参数 α、β 决定

你可以再补一句很实用的定性判断：

- 若延迟 α 很大（启动开销重），不要把 p 开太大
- 若矩阵很大（n 很大），计算更重，可以用更大的 p
