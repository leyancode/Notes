**Question**  
**What is a collective operation in MPI?**  
什么是 MPI 中的 collective operation？
 
**Definition** **定义**  
在 MPI 中，**collective operation** 是一种：

- 必须由 **communicator** **中的所有** **MPI processes** 调用的操作
- 调用范围严格限定在同一个 communicator 内

英文原定义要点：  
In MPI, a collective operation is an operation that must be called by all MPI processes belonging to the communicator considered.
 
**Consequence** **后果与约束**

- 如果 communicator 中 **哪怕有一个** **MPI process** **没有调用该** **collective operation****￼**→ 会 **保证发生** **deadlock****（死锁）**
- 这一规则 **同样适用于** **non-blocking collective operations**
    - 即使 collective 本身是 non-blocking
    - 对应的 MPI_Wait 也 **必然** **deadlock**

关键词总结：

- collective operation
- communicator
- deadlock
- non-blocking operations
- MPI_Wait

**Broadcast** **广播操作（****MPI_Bcast****）**

![Exported image](Exported%20image%2020260730160735-1.png)

**The broadcast, with a single element**  
单元素广播  
图示说明：

- 存在一个 root process（记为 Proot）
- Proot 中持有单个元素 E0
- 调用 broadcast 后：
    - 所有进程 P0、P1、P2 中的 buffer 都包含同一个 E0
- 数据流方向：**one-to-all**

要点总结：

- 只有 root process 提供有效的发送数据
- 其他进程在调用前 buffer 内容不重要
- 调用结束后，所有进程 buffer 内容一致
 
**The broadcast, with multiple elements**  
多元素广播

![Exported image](Exported%20image%2020260730160739-2.png)

图示说明：

- Proot 持有多个连续元素 E0, E1
- 调用 broadcast 后：
    - 每个进程都收到同样的元素序列 E0, E1
- 广播的是一个 **array / contiguous buffer**

关键点：

- broadcast 不关心“语义”，只关心：
    - buffer 起始地址
    - count
    - datatype
- 元素数量由 count 决定，而不是 communicator size
 
**MPI_Bcast** **接口定义**

![Exported image](Exported%20image%2020260730160740-3.png)

int MPI_Bcast(￼ void* buffer,￼ int count,￼ MPI_Datatype datatype,￼ int emitter_rank,￼ MPI_Comm communicator￼);  
参数含义说明：

- buffer
    - root：发送缓冲区
    - 非 root：接收缓冲区
- count
    - 广播的元素个数（不是字节数）
- datatype
    - 每个元素的 MPI_Datatype
- emitter_rank
    - root process 在 communicator 中的 rank
- communicator
    - 所有参与 broadcast 的进程集合

重要语义约束：

- communicator 中 **所有进程必须调用** **MPI_Bcast**
- root 与非 root 的 buffer 类型、count、datatype 必须一致
- 否则行为是 undefined，极易 deadlock
 
**Reduction** **归约操作（****MPI_Reduce****）**  
**The reduction, with a single element**  
单元素归约

![Image](Exported%20image%2020260730160741-4.png)  
![Image](Exported%20image%2020260730160742-5.png)  
![Exported image](Exported%20image%2020260730160743-6.png)

￼图示说明：

- 每个进程 P0、P1、P2 各自持有一个元素：
    - E0, E1, E2
- 使用归约算子 ⊕（如 sum, max 等）
- 最终结果：
    - E0 ⊕ E1 ⊕ E2
    - 只存放在 Proot 中

核心语义：

- many-to-one
- 非 root 进程不会得到归约结果
- operation 必须是 associative
 
**The reduction, with multiple elements**  
多元素归约

![Image](Exported%20image%2020260730160743-7.png)  
![Image](Exported%20image%2020260730160744-8.png)  
![Exported image](Exported%20image%2020260730160748-9.png)

图示说明：

- 每个进程持有一个元素数组
    - P0: E0, E3
    - P1: E1, E4
    - P2: E2, E5
- 归约是 **逐元素进行的**：
    - 第一个位置：E0 ⊕ E1 ⊕ E2
    - 第二个位置：E3 ⊕ E4 ⊕ E5
- 最终结果数组仅存在于 Proot

关键理解点：

- MPI_Reduce 并不是“把数组拼起来”
- 而是对同一 index 上的元素做 reduction
 
**MPI_Reduce** **接口定义**

![Exported image](Exported%20image%2020260730160749-10.png)

int MPI_Reduce(￼ const void* send_buffer,￼ void* receive_buffer,￼ int count,￼ MPI_Datatype datatype,￼ MPI_Op operation,￼ int root,￼ MPI_Comm communicator￼);  
参数要点：

- send_buffer
    - 所有进程都必须提供
- receive_buffer
    - 只有 root 进程有效
    - 非 root 可传 NULL 或无效指针（但仍需调用）
- operation
    - MPI_Op，如 MPI_SUM, MPI_MAX
    - 或 user-defined reduction operator

重要约束：

- operation 必须满足 associativity
- 若标记为 commutative，则允许任意组合顺序
 
**Scatter** **分发操作（****MPI_Scatter****）**  
**The scatter, with a single element**  
单元素 scatter
 ![Image](Exported%20image%2020260730160750-11.png) ![Image](Exported%20image%2020260730160751-12.png)

图示说明：、

![Exported image](Exported%20image%2020260730160752-13.png)

- Proot 持有一个数组：E0, E1, E2
- scatter 后：
    - P0 接收 E0
    - P1 接收 E1
    - P2 接收 E2
- 数据流方向：**one-to-many****（分块）**

理解重点：

- 与 broadcast 不同
- 每个进程只接收属于自己的那一部分
 
**The scatter, with multiple consecutive elements**  
连续多元素 scatter

![Image](Exported%20image%2020260730160753-14.png)

![Exported image](Exported%20image%2020260730160758-16.png)

- Proot 持有 6 个连续元素：E0–E5
- 每个进程接收一个连续 block：
    - P0: E0, E1
    - P1: E2, E3
    - P2: E4, E5

关键点：

- 默认 scatter 假设数据在 root 上是 **contiguous layout**
- block size = count
 
**The scatter, with a (resized) vector**

![Exported image](Exported%20image%2020260730160759-17.png)

使用 resized vector 的 scatter

- 原始数据仍是 E0–E5

    - P0: E0, E3
    - P1: E1, E4
    - P2: E2, E5

重要思想：

- scatter 的分发方式不仅由数据本身决定
- 还由 datatype 的 extent 和 layout 决定
- 这是 Advanced Collective 的重要基础
   

**Scatter** **接口补充（****MPI_Scatter****）**

![Exported image](Exported%20image%2020260730160800-18.png)

**MPI_Scatter** **接口定义**

![Exported image](Exported%20image%2020260730160800-19.png)

int MPI_Scatter(￼ const void* buffer_send,￼ int count_send,￼ MPI_Datatype datatype_send,￼ void* buffer_recv,￼ int count_recv,￼ MPI_Datatype datatype_recv,￼ int root,￼ MPI_Comm communicator￼);  
参数语义说明：

- buffer_send
    - 仅在 root process 上有效
    - 包含所有将被分发的数据
- count_send / datatype_send
    - 描述 **发送给每一个进程的** **block** **大小和类型**

    - 描述接收缓冲区中期望的数据布局
- root
    - scatter 的数据源进程
- communicator
    - 参与 scatter 的进程集合

关键语义约束：

- communicator 中 **所有进程必须调用** **MPI_Scatter**
- send 与 recv 的 datatype / count 必须在语义上匹配
- root 上的数据 layout 由 datatype_send 决定，而不是数组本身
 
**Gather** **收集操作（****MPI_Gather****）**  
**The gather, with a single element**  
单元素 gather  
图示说明：

- 每个进程 P0、P1、P2 各自持有一个元素：
    - E0, E1, E2
- gather 后：
    - 所有元素被收集到 Proot
    - 在 Proot 的 buffer 中形成一个连续序列

核心理解：

- gather 是 scatter 的“反向操作”
- 数据流方向：**many-to-one**
- 非 root 进程不会得到最终收集结果
 
**The gather, with multiple consecutive elements**  
连续多元素 gather

![Image](Exported%20image%2020260730160802-21.png)  
![Image](Exported%20image%2020260730160804-22.png)

图示说明：

- 每个进程发送多个连续元素
- Proot 按 rank 顺序将它们拼接：
    - P0 → P1 → P2
- 最终在 root 上形成一个大数组 E0–E5

关键点：

- gather 默认假设：
    - 每个进程发送的 block 在本地是 contiguous
    - root 上接收缓冲区也是 contiguous
 
**The gather, with a (resized) vector**  
使用 resized vector 的 gather

![Image](Exported%20image%2020260730160808-23.jpeg)  
![Exported image](Exported%20image%2020260730160808-24.png)

图示说明：

- 各进程发送的数据在逻辑上并不连续：
    - P0: E0, E3
    - P1: E1, E4
    - P2: E2, E5
- 通过 **derived datatype****（****resized vector****）**
    - 在 Proot 上重新排列为：
        - E0, E1, E2, E3, E4, E5

重要思想：

- gather 的排列顺序由 **datatype extent** **和** **displacement** 决定
- 不只是简单的 memcpy
- 是 Advanced Collective 的核心动机之一

**MPI_Gather** **接口定义**

![Exported image](Exported%20image%2020260730160811-26.png)

**Barrier** **同步操作（****MPI_Barrier****）**  
**The barrier, assuming two MPI processes**  
Barrier 同步示意（两个进程）

![Image](Exported%20image%2020260730160812-27.png)  
![Image](Exported%20image%2020260730160813-28.png)

- MPI process 0 与 MPI process 1 都调用 MPI_Barrier

**Inclusive Scan****（****MPI_Scan****）**  
Inclusive scan 可以理解为 **prefix reduction****（前缀归约，包含自身）**。
 
**The inclusive scan, with a single element**  
单元素 inclusive scan

![Image](Exported%20image%2020260730160818-31.png)  
![Exported image](Exported%20image%2020260730160819-32.png)  

图示说明（假设进程 rank 顺序为 P0, P1, P2）：

- 每个进程各自拥有一个元素：
    - P0: E0
    - P1: E1
    - P2: E2
- 执行 inclusive scan 后，各进程得到的结果为：
    - P0: E0
    - P1: E0 ⊕ E1
    - P2: E0 ⊕ E1 ⊕ E2

核心语义：

- 每个进程得到的是￼**从** **rank 0** **到当前** **rank** **的** **reduction** **结果**
- 包含当前进程自己的元素
 
**The inclusive scan, with multiple elements**  
多元素 inclusive scan
   
![Image](Exported%20image%2020260730160820-33.png)  
![Image](Exported%20image%2020260730160821-34.png) ![Exported image](Exported%20image%2020260730160822-35.png)  

图示说明：

- 每个进程持有多个元素（数组）
- scan 操作是 **逐元素（****element-wise****）进行的**
- 对于同一 index：
    - P0 得到自身的值
    - P1 得到 P0 ⊕ P1
    - P2 得到 P0 ⊕ P1 ⊕ P2

关键理解点：

- MPI_Scan 并不是把数组拼接
- 而是对每个位置独立做 prefix reduction
- 与 MPI_Reduce 的 element-wise 语义一致，只是结果分布不同
 
**MPI_Scan** **接口定义**

![Exported image](Exported%20image%2020260730160823-36.png)

int MPI_Scan(￼ const void* send_buffer,￼ void* receive_buffer,￼ int count,￼ MPI_Datatype datatype,￼ MPI_Op operation,￼ MPI_Comm communicator￼);  
参数要点：

- send_buffer
    - 本进程提供的输入数据
- receive_buffer
    - 本进程接收 prefix reduction 结果
- count / datatype
    - 指定参与 scan 的元素数量与类型
- operation
    - reduction operator，必须满足 associativity
- communicator
    - 所有参与 scan 的进程集合

重要语义约束：

- communicator 中所有进程必须调用
- operation 的组合顺序遵循 rank 顺序
- 与 MPI_Reduce 不同，**每个进程都会得到结果**
 
**Exclusive Scan****（****MPI_Exscan****）**  
Exclusive scan 是 **不包含自身的** **prefix reduction**。
 
**The exclusive scan, with a single element**  
单元素 exclusive scan

![Image](Exported%20image%2020260730160827-37.png)  
![Image](Exported%20image%2020260730160829-38.png)  
![Exported image](Exported%20image%2020260730160830-39.png)

￼图示说明：

- 每个进程仍然有一个元素 E0, E1, E2
- 执行 exclusive scan 后：
    - P0: 无定义值（没有比它 rank 更小的进程）
    - P1: E0
    - P2: E0 ⊕ E1

核心差异点：

- 结果 **不包含当前进程自己的输入**
- 对 rank = 0 的进程，结果是 undefined
 
**The exclusive scan, with multiple elements**  
多元素 exclusive scan
   
![Image](Exported%20image%2020260730160831-40.png)  
![Exported image](Exported%20image%2020260730160832-41.png)

￼图示说明：

- 对每个数组元素位置：
    - P1 得到 P0 的值
    - P2 得到 P0 ⊕ P1
- 当前进程的数据不参与自己的结果计算

重要理解：

- MPI_Exscan 在语义上等价于：
    - MPI_Scan 的结果
    - 向右整体平移一位（conceptually）
- 但实现和语义由 MPI 保证，不是用户手动移动
 
**MPI_Exscan** **接口定义**  
int MPI_Exscan(￼ const void* send_buffer,￼ void* receive_buffer,￼ int count,￼ MPI_Datatype datatype,￼ MPI_Op operation,￼ MPI_Comm communicator￼);

![Exported image](Exported%20image%2020260730160833-42.png)

关键语义点：

- 所有进程必须调用 MPI_Exscan
- reduction operator 必须是 associative
- rank 0 的 receive_buffer 内容是 undefined
- 常用于：
    - prefix sums
    - offsets 计算
    - 并行数据分区（如 CSR 行指针）
 
**Scan** **与** **Reduce** **的关系总结（概念层面）**

- MPI_Reduce
    - many-to-one
    - 结果只在 root
- MPI_Scan
    - many-to-many
    - inclusive prefix reduction
- MPI_Exscan
    - many-to-many
    - exclusive prefix reduction
   

**3 Vector versions of collectives**  
向量版本的集合通信
 
**动机** **Motivation**  
**Convenient case****（理想情况）**

![Exported image](Exported%20image%2020260730160834-43.png)

常见场景：

- 有 **6** **个** **datatype T** **的元素**
- 需要 scatter 给 **3** **个** **MPI processes**
- 每个进程接收 **相同数量** 的元素

数据示意：  
T0 T1 T2 T3 T4 T5  
使用经典 MPI_Scatter 即可：  
MPI_Scatter(￼ buffer_send, 2, T,￼ buffer_recv, 2, T,￼ root_rank, comm￼);  
分发结果（按 rank 顺序）：

- P0: T0 T1
- P1: T2 T3
- P2: T4 T5

结论：

- 当 **每个进程接收的** **count** **相同**
- 且数据在 root 上是规则排列的￼→ MPI_Scatter 是最简洁、最自然的选择
 
**Less convenient case****（不理想情况）**

![Exported image](Exported%20image%2020260730160838-44.png)

问题提出：

- 如果由于 **load imbalance** 等原因
- 不同 MPI process 希望接收 **不同数量的元素**
- 例如：
    - P0: 3 个元素
    - P1: 1 个元素
    - P2: 2 个元素

此时：

- MPI_Scatter **无法表达这种不均匀分发**
- 因为它假设：
    - 所有进程 count_send 相同

这正是 **vector versions of collectives** 的使用场景。
 
**Classic vs Vector versions**  
**对比关系**

![Exported image](Exported%20image%2020260730160839-45.png)  

|   |   |
|---|---|
|**Classic version**|**Vector version**|
|MPI_Scatter|MPI_Scatterv|
|MPI_Gather|MPI_Gatherv|

核心区别一句话总结：

- Classic version：
    - 每个进程的 count 相同
- Vector version：
    - 每个进程的 count 和 displacement 可以不同
 
**MPI_Scatterv**  
**接口定义**

![Exported image](Exported%20image%2020260730160840-46.png)

int MPI_Scatterv(￼ const void* buffer_send,￼ const int counts_send[],￼ const int displacements[],￼ MPI_Datatype datatype_send,￼ void* buffer_recv,￼ int count_recv,￼ MPI_Datatype datatype_recv,￼ int root,￼ MPI_Comm communicator￼);  
关键变化点：

- counts_send 变成数组
    - counts_send[i] 表示 **发送给** **rank i** **的元素数量**
- displacements 变成数组
    - displacements[i] 表示 **rank i** **数据在** **send buffer** **中的起始位置**
    - 单位是 **datatype_send** **的** **extent**

其余语义保持与 MPI_Scatter 一致。
 
**使用示例：解决原始问题**  
问题设定：  
T0 T1 T2 T3 T4 T5  
希望分发为：

- P0: T0 T1 T2
- P1: T3
- P2: T4 T5

参数设置：  
int counts[] = {3, 1, 2};￼int displacements[] = {0, 3, 4}; // 0, 0+3, 0+3+1  
MPI_Scatterv(￼ buffer_send,￼ counts,￼ displacements,￼ T,￼ buffer_recv,￼ counts[my_rank],￼ T,￼ root,￼ comm￼);  
理解要点：

- displacements 是 **prefix sum of counts**
- 每个进程：
    - 接收 counts[my_rank] 个元素
- root 负责描述 **全局数据布局**
 
**MPI_Gatherv**  
**接口定义**

**Vector collectives vs Derived datatypes**  
重要区分点（非常容易混）  
**不要混淆** **Don’t confuse**

![Exported image](Exported%20image%2020260730160844-49.png)

- **Derived datatypes**
    - 描述的是：
        - 一个 logical element 内部的结构
        - counts、displacements、types 如何组成 **一个元素**
    - 关注的是 **element** **内部布局**
- **Vector collective operations**
    - 描述的是：
        - 不同 MPI processes 之间
        - element 的数量和位置如何分布
    - 关注的是 **element** **之间的分布**

一句话对比总结：

- Derived datatype
    - 解决“一个元素长什么样”
- Vector collective
    - 解决“每个进程拿多少个元素，从哪里拿”
 
**本节核心总结**

- MPI_Scatter / MPI_Gather
    - 适用于均匀分布
- MPI_Scatterv / MPI_Gatherv
    - 适用于不均匀分布（load imbalance）
- Vector collectives ≠ Derived datatypes
    - 一个解决 **进程间不均匀**
    - 一个解决 **内存布局复杂**
