主题一句话  
MPI Shared Memory 的动机：减少同一节点上多个 MPI processes 的重复数据副本，从而节省内存。  
核心讲解  
动机（为什么需要）  
在传统 MPI 程序中，每个 MPI process 都拥有自己的独立地址空间。这意味着：  
每个 process 都会分配自己的一份数据。  
如果程序需要一个大型数据结构，例如：  
lookup table  
大型常量数组  
预计算数据￼  
那么每个 MPI process 都会创建一份副本。  
当程序运行在 HPC 集群上时，这种设计会带来严重的内存浪费。  
例子：  
假设：￼

![Exported image](Exported%20image%2020260730161147-0.png)

每个节点运行 128 个 MPI processes  
某个数据结构大小 = 1 GB  
由于 MPI 默认模型是：  
每个 process 一份数据  
因此：  
总内存占用 = 128 × 1GB = 128GB￼  
但实际上：  
只有一份数据是必要的。  
因此真正有效数据 = 1GB  
冗余数据 = 127GB  
这就是 duplication overhead（数据复制开销）。￼  
定义或本质（是什么）  
==Shared memory====（共享内存）是一种机制，使得：==  
==同一== ==node== ==上的多个== ==MPI processes==  
==可以访问同一块物理内存。==  
核心思想：  
不是每个 process 各自保存一份数据  
而是所有 process 共享一份数据。￼  
换句话说：￼  
原来结构  
Process 0 → copy A  
Process 1 → copy A  
Process 2 → copy A  
Process 3 → copy A  
共享内存结构  
Shared memory region → A  
Process 0 → reference  
Process 1 → reference  
Process 2 → reference  
Process 3 → reference  
这样可以显著减少 memory footprint（内存占用）。  
使用或推理（怎么实现）￼  
为了让 MPI processes 共享内存，需要两个步骤：  
步骤 1  
找到能够共享内存的 MPI processes。  
前提条件：  
这些 processes 必须在同一个 node 上。  
因为：  
不同 node 的内存是物理隔离的。  
因此第一件事是：  
==识别同一== ==node== ==的== ==processes====。==￼￼  
步骤 2  
让这些 processes 访问同一块内存。  
也就是说：  
==创建一个== ==shared memory region==  
然后所有本节点 processes 都能：  
read  
write  
访问该数据。  
关键细节  
关键前提  
Shared memory 只能在同一个 node 内部使用。  
原因：  
node 之间是分布式内存系统（distributed memory）。￼  
重要概念  
node  
一台物理计算节点  
MPI process  
一个独立地址空间的进程  
duplication overhead  
由于每个 process 复制数据导致的内存浪费  
shared memory  
多个进程访问同一物理内存区域￼  
练习题  
问题  
假设：  
一个节点运行 64 个 MPI processes  
每个 process 都存储一个 2GB lookup table  
问题：  
1 当前总内存使用是多少

答案  
步骤 1 计算当前内存

步骤 2 共享内存

How it works

MPI Shared Memory 的基本实现机制

主题一句话  
MPI Shared Memory 的基本工作流程：先找到同一 node 的 processes，再创建 shared window，使这些 processes 可以直接访问同一块内存。￼  
核心讲解  
动机与位置  
前一部分说明了为什么需要 shared memory：  
为了避免同一节点上 MPI processes 各自保存重复数据。  
这一部分解释的是：  
MPI 如何实现 shared memory。  
整体流程可以理解为一个四步过程：  
1 分组（找到同一 node 的 processes）  
2 创建共享内存窗口（shared window）  
3 获取其他进程的内存地址  
4 直接访问该内存￼  
机制或流程  
第一步  
Splitting MPI processes（进程分组）  
==MPI== ==程序启动后，所有== ==processes== ==默认属于：==  
==MPI_COMM_WORLD==  
但并不是所有 processes 都在同一 node 上。  
因此第一件事是：￼  
把 MPI processes 按 node 重新分组。  
结果是：  
node 0 的 processes → 一个 communicator  
node 1 的 processes → 一个 communicator  
node 2 的 processes → 一个 communicator  
这样每个 communicator 中的 processes 都可以共享内存。￼  
第二步  
Create MPI windows as shared（创建共享内存窗口）  
MPI 使用一种叫做 window 的机制表示可访问的内存区域。￼  
window（MPI window）  
是一块可以被 MPI 访问的 memory region。  
如果创建的是：  
shared window  
那么同一 node 的 processes 可以共享这一块内存。￼  
第三步  
Find where windows of other processes reside（获取内存位置）  
==每个== ==process== ==需要知道：==  
==其他== ==process== ==的== ==shared window== ==在哪里==。  
因此 MPI 会提供接口来查询：  
其他 process 的 memory address  
以及对应大小。￼  
第四步  
Direct access（直接访问）  
完成前面步骤后：  
process 可以直接访问该内存。  
例如：  
process 0  
可以直接读写 process 1 的 shared memory。  
这种访问方式：  
不需要 MPI_Send  
不需要 MPI_Recv￼  
本质上变成：  
普通内存访问（load / store）。  
流程总结（逻辑顺序）  
完整执行逻辑可以写成：￼  
Step 1  
Split communicator by node  
Step 2  
Create shared memory window  
Step 3  
Query addresses of shared memory  
Step 4  
Directly read/write the memory￼  
关键细节  
MPI window（MPI 窗口）  
MPI RMA（Remote Memory Access）模型中的概念。  
表示：  
一块可以被其他 processes 访问的内存。  
shared window  
特殊类型的 window：  
多个 processes 在同一 node 共享同一物理内存。  
direct memory access  
访问方式类似：  
array[index]  
而不是：  
MPI communication。￼  
常见误解  
==shared memory== ==不等于跨节点共享。==  
==共享只发生在：==  
==同一== ==node== ==内部。==  
==跨节点仍然必须使用：==  
==MPI communication====。====￼==

主题一句话  
MPI 通过 communicator splitting（通信器划分）把 processes 按规则分组，从而识别哪些进程可以共享资源，例如同一 node 的 shared memory。￼  
核心讲解

==在== ==MPI== ==程序中，所有进程默认属于：==

MPI Shared Memory 的核心实现：通过 MPI_Win_allocate_shared 创建 shared window，并通过 MPI_Win_shared_query 获取其他进程的内存地址，从而实现直接内存访问。  
核心讲解  
动机与位置  
前一部分已经完成两个关键步骤：  
1 通过 communicator splitting 找到同一 node 的 processes  
2 把这些 processes 放入同一个 communicator  
接下来需要解决的问题是：  
==如何让这些== ==processes== ==实际共享同一块物理内存。==￼  
MPI 的解决方案是：  
Shared Window（共享窗口）。  
通过 MPI Window 机制，多个进程可以暴露自己的内存区域，并允许其他进程访问。  
核心概念￼  
shared window  
shared window 是一块被多个 MPI processes 共享的 memory region。  
特点：  
同一 node 上的 processes

array[i]  
而不是：  
MPI_Send  
MPI_Recv
