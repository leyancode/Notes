# LLM 采样：temperature 与 softmax

## 1. 这个问题在面试中考什么？

考的是「LLM 是怎么从模型输出变成一个具体 token 的」这条链路，以及在 Agent / function calling 里为什么要把随机性调低。高频出现在 Agent 岗、推理/采样、以及「你怎么保证工具调用稳定」这类追问里。

## 2. 重要程度总览

| 知识点 | 重要程度 | 一句话 |
|---|---|---|
| softmax 把 logits 变成概率分布 | 必须掌握 | LLM 输出层和 attention 都靠它 |
| temperature 控制采样随机性 | 必须掌握 | 缩放 logits，改变分布尖锐/平缓 |
| function calling 为什么调低温度 | 必须掌握 | 要结构精确 + 可复现 |
| softmax 是不是激活函数 | 需要掌握 | 是，但作用在整个向量上，非逐元素 |
| softmax 的效率替代方案 | 了解即可 | hierarchical / sampled softmax、linear attention |

## 3. 核心知识表格

| 参数 / 概念 | 作用对象 | 核心作用 | 面试关键词 |
|---|---|---|---|
| softmax | logits 向量 | 归一化成和为 1 的概率分布 | 概率分布、可微 argmax、竞争 |
| temperature $T$ | softmax 前的 logits | 缩放 logits，调随机性 | 尖锐 vs 平缓、$T\to 0$ 贪心 |
| top_p | softmax 后的候选集 | 按累积概率截断再采样 | nucleus sampling、别和 T 同调 |

## 4. 高频问题整理

### 4.1 temperature 是做什么的？

> [!important]- 必须掌握
> Agent / function calling 岗高频。必须能说清它缩放的是 logits、$T\to 0$ 趋于确定性、以及为什么工具调用场景要调低。

> [!summary]- 核心结论
> temperature 是采样时对 logits 的缩放因子，插在 softmax 前：$p_i = \mathrm{softmax}(\mathrm{logits}_i / T)$。$T$ 越小分布越尖锐、越确定；$T$ 越大分布越平、越随机。它控制的是随机性/多样性，不是「聪明程度」。

> [!question]- 面试怎么答
> temperature 是采样温度，作用是在 softmax 之前把每个 logit 除以 $T$。$T$ 趋近 0 时分布被拉尖，几乎总选概率最高的 token，等价于贪心 argmax，输出确定可复现；$T$ 等于 1 用原始分布采样；$T$ 大于 1 把分布抹平，低概率 token 也有机会被选中，输出更发散。它只改变随机性，不会让模型「更有创造力地想到新知识」。

> [!example]- 具体例子
> 三个候选 token 的 logits 是 [4, 2, 1]。$T=0.1$ 时第一个的概率被推到接近 1，几乎必选它；$T=2$ 时三者概率被拉平，第二、第三个也常被采到。同一个 prompt 反复跑，低温度输出几乎一样，高温度每次不同。

> [!warning]- 常见误区
> ①「高温度 = 更聪明」错，只是更随机。②「$T=0$ 就 100% 可复现」不严格：浮点运算顺序、批处理、分布式后端会带来微小非确定性，要更强复现性需配合 seed。③ 别和 top_p 同时乱调，官方建议两者只动一个。

> [!note]- 关键词
> logits 缩放、softmax 前、$T\to 0$ 贪心、随机性 vs 多样性、seed、top_p

### 4.2 function calling 里 temperature 该怎么设？

> [!important]- 必须掌握
> 这是 Agent 岗把「原理」落到「工程决策」的点，几乎必问：你怎么保证工具调用稳定。

> [!summary]- 核心结论
> function calling 要的是结构化、可解析、可复现的输出（选对函数、参数名对、JSON 合法、枚举值合法），不要多样性。所以一般把 temperature 设为 0 或接近 0。

> [!question]- 面试怎么答
> function calling 的目标是让模型输出结构化的工具调用，要精确和可复现，所以我把 temperature 调到 0。温度偏高时模型可能挑一个次优但说得通的函数、给可选参数填不该填的值、偶发破坏 JSON 或选到不在 enum 里的值。如果我要评测「规则 router vs LLM router」的准确率，LLM 侧也必须 $T=0$，否则每次跑分都在抖，没法公平对比。

> [!example]- 具体例子
> 用户问「1000 核的扩展性如何」。$T=0$ 时稳定路由到同一个 analyze_scaling 工具、同一组参数，方便调试和回归；若 $T=0.8$，偶尔会路由到相近但不对的工具，或把可选的 baseline 参数乱填。

> [!tip]- 记忆方法
> 「路由 / 取参要稳 → 关温度」，只有 brainstorm、生成多样测试输入这种「故意要多个候选」的场景才调高。

> [!note]- 关键词
> 结构化输出、可复现、评测公平性、enum 越界、JSON 合法性

### 4.3 softmax 是激活函数吗？

> [!info]- 需要掌握
> 是个容易被追问的「概念边界」题，答对能体现你懂 softmax 和 ReLU 的本质区别。

> [!summary]- 核心结论
> 是——框架（如 PyTorch 的 `nn.Softmax` 与 `nn.ReLU` 并列）和习惯都把它归为激活函数。但它和 ReLU/sigmoid 有本质区别：后者是逐元素（element-wise）的，softmax 是向量到向量、分量互相耦合竞争的。

> [!question]- 面试怎么答
> softmax 通常被归类为激活函数，常用在多分类输出层。但它跟 ReLU、sigmoid 不同：那些是逐元素函数，$\mathrm{sigmoid}(x_i)$ 只依赖 $x_i$；而 softmax 的分母对整个向量求和，第 $i$ 个输出依赖全部输入，各分量之间是竞争关系——某个 logit 变大会把别的分量挤小，因为总和恒为 1。所以严格派更愿意叫它归一化 / 概率化操作。

> [!example]- 具体例子
> 公式 $\mathrm{softmax}(x)_i = \dfrac{\exp(x_i)}{\sum_j \exp(x_j)}$。分母那个 $\sum_j$ 把所有分量牵进来，这就是它「非逐元素」的根源，也是 temperature 能全局调节整个分布的原因——$T$ 缩放的是进 softmax 的每个 $x_i$。

> [!warning]- 常见误区
> 把 softmax 当成和 ReLU 一样的逐元素激活。它的关键特征是「竞争 + 归一化」，名字 soft-max 就是 argmax 的平滑可微版本。

> [!note]- 关键词
> 逐元素 vs 向量级、归一化、竞争、可微 argmax、总和为 1

### 4.4 LLM 都用 softmax 吗？

> [!info]- 需要掌握
> 考你是否知道 softmax 在 LLM 里出现两处（输出层 + attention），以及是否了解效率替代方案。

> [!summary]- 核心结论
> 是，主流自回归 LLM 两处都用：① 每层 attention 内部用 softmax 把相关性打分归一化成注意力权重；② 输出层用 softmax 在整个词表上算概率分布再采样。存在效率替代方案，但标准 softmax 仍是绝大多数模型的实际做法。

> [!question]- 面试怎么答
> 是。一个 LLM 里 softmax 出现不止一次：每层每个注意力头都有一次 $\mathrm{softmax}(QK^\top/\sqrt{d})V$，最后输出层还有一次——对长度等于词表大小的 logits 做 softmax，得到 next-token 的概率分布，再配合 temperature、top_p 采样。因为 next-token 是从词表里单选一个（多分类），所以用 softmax 而不是 sigmoid；sigmoid 用于多标签那种每类独立判断是/否的场景。

> [!example]- 具体例子
> attention: $\mathrm{Attention}(Q,K,V) = \mathrm{softmax}\!\left(\dfrac{QK^\top}{\sqrt{d}}\right)V$，softmax 把每个 token 对其它 token 的相关性归一化成和为 1 的权重。输出层：词表几万到十几万维的 logits 过 softmax → 概率分布 → 采样。

> [!note]- 了解即可
> 效率替代：词表 softmax 分母要对几万个词求和，代价高，于是有 hierarchical softmax、sampled softmax、NCE（训练期近似）；attention 侧有 linear attention、Performer、softmax-free attention 等探索。但这些多在研究或特定高效模型里，通用大模型仍以标准 softmax 为主。

> [!warning]- 常见误区
> ① 以为 softmax 只在输出层，忘了 attention 内部。② 把 next-token 说成 sigmoid：单选用 softmax，多标签才用 sigmoid。

## 5. 流程梳理：从模型输出到一个 token

$$\text{最后一层} \Rightarrow \text{logits（词表维）} \xrightarrow{\ \div T\ } \text{softmax} \Rightarrow \text{概率分布} \xrightarrow{\text{top\_p 截断}} \text{采样} \Rightarrow \text{token}$$

> [!summary]- 核心结论
> temperature 在 softmax 前动手，top_p 在 softmax 后动手，两者都只影响「怎么选」，不改变模型本身学到的知识。理解这条链路 + softmax，基本就掌握了 LLM 采样行为的一大半。

## 6. 常见误区

> [!warning]- 常见误区
> ① 高温度 = 更聪明（错，只是更随机）。② $T=0$ 严格可复现（近似，非绝对，需配 seed）。③ temperature 和 top_p 同时乱调（建议只动一个）。④ softmax 是逐元素激活（错，向量级、分量竞争）。⑤ LLM 只在输出层用 softmax（attention 里也用）。⑥ next-token 用 sigmoid（单选用 softmax）。

## 7. 面试口述版答案

> [!question]- 面试怎么答（30 秒综合版）
> LLM 每步预测下一个 token：最后一层输出词表维的 logits，除以 temperature 后过 softmax 得到概率分布，再配合 top_p 采样。softmax 把一组 logits 归一化成和为 1 的分布，是可微的 argmax，输出层和 attention 里都用它。temperature 控制随机性——趋近 0 就接近贪心、确定可复现，越大越发散。所以在 Agent 的 function calling 里我把 temperature 设成 0：要的是结构精确、工具调用稳定、评测可复现，而不是多样性。

## 9. 最终速记版

> [!tip]- 一句话速记
> softmax 把 logits 变概率（输出层 + attention 都用，向量级竞争）；temperature 在 softmax 前缩放 logits 调随机性，$T\to 0$ 趋于确定；function calling 要稳、要复现，所以温度设 0。
